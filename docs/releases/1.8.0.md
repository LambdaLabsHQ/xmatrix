# xMatrix 1.8.0

Changes since 1.7.0. This release updates the stable Web and CLI/daemon. It also
brings Web improvements made since the last stable Web, 1.6.0, to everyone
using xmatrix.sh or a stable native app's hosted interface.

## Write and send with less interruption

- Mentions in the message editor show the same faces and chips as sent
  messages. You can still edit their text, use plain-text paste, undo changes
  and compose with an input method.
- Send a message while its files are uploading. A pending message shows local
  previews and upload progress; the conversation receives the message only
  when all its files are ready. Failed uploads can be retried or discarded.
- Search results stay in the search panel, with an option to search older
  messages there. Recent searches refill the field. Old full-page search links
  open the conversation list instead.
- Message actions sit on one bar at the row's top edge, with one-click common
  reactions and Reply and Copy controls. Edit and Recall are in the menu for
  your own messages. Hovered messages support R, C and E shortcuts when you
  are not typing or selecting text.

## Follow work on Pages

- Agent replies can show cards naming the Pages and sections they changed,
  with readable additions, rewrites and removals. Open a card to see those
  changes on the Page, then return to the original message.
- A Page's Agent mention shows dispatch, startup and failure status to the
  person who summoned it. The status stays attached to that mention as text
  moves and survives a reload on that device.
- Hovering a discussion card highlights its passage or section, including
  when its original quoted passage has been rewritten away.
- Committed Page edits appear whole. Streamed words appear as the Hub accepts
  them, without delayed replay that could make headings or tables look
  truncated. Updated daemons pace live co-writing at the sending interface
  and retry refused chunks without repeating accepted text.
- Opening a conversation containing both Page bookmarks and Agent edit cards
  no longer crashes the screen because the two readers disagree about a
  cached revision's format. Page bylines also group an Agent's repeated Runs
  under one author.
- Starting co-writing or replacing a quiet co-writer reliably sends the Agent
  its first request. Failed Page summons show their cause on the mention chip.

## A clearer Web experience

- Conversation history keeps ordinary messages whole; later messages do not
  fold earlier ones as obsolete. The timeline moves more smoothly at its end,
  and message and Page lists have tighter spacing. Pages also use a smaller
  gap between paragraphs so they read as documents rather than double-spaced
  conversations.
- On phones, a conversation opened from a notification returns to the Channel
  list. App sign-in that requires a second factor returns to the app after
  verification instead of leaving the session inside the sign-in sheet.
- Sign-in leads with email and offers Apple, Google and GitHub as separate
  round buttons. The phone layout uses full-width artwork with safe-area
  spacing.
- Connector command chips show the App's whole mark instead of cropping it.
- The public site has a Simplified Chinese homepage at /zh, a phone-sized app
  preview on phones, richer shared-link cards and a single glass navigation
  bar with a smoother scroll transition. X connector credit rates are in the
  connector guide.

## Compatibility and upgrade

- Reload the stable Web to use the new interface. Run `xmatrix update` for the
  stable CLI/daemon, then reborn or restart existing Agent Instances that need
  the updated co-writing runtime.
- Older daemons can still write Pages. The new live-writing pacing applies to
  updated runtimes; complete message-based writes and committed Page edits
  still arrive whole.
- Desktop, Android and iOS native shells are not rebuilt in this release.
  Their stable hosted Web receives the interface changes; the existing iOS
  App Review submission is unchanged.
- No account migration or manual database operation is required.

## Known limitations

- A Page summon status is remembered on the caller's device; other readers
  see an ordinary mention. Page-level discussion cards have no single passage
  to highlight.
- An uploading message remains pending until every file is ready. Updating the
  daemon does not replace already-running Agent processes.
- Intermittent database, runtime delivery and credential verification failures
  remain under investigation; this release does not establish that all their
  underlying causes are fixed.
- This release does not automatically open its notes. Exact-version links in
  updates and downloads remain available.
