# xMatrix 3.1.0

Settings an Agent needs can now be completed in its conversation. Pages gain
inline formatting on a selection, and Agents start sooner and recover from
used-up provider quota when a fresh reading shows it is available again.

## Complete a setting where the work stopped

A stopped app command can show its missing setting under the receipt. An Agent
can also ask for several settings on one card with
`xmatrix settings ask <address>… --reason "…"`, and read their state with
`xmatrix settings status <address>…`. These commands are supplied by the service
and already work with CLI 3.0.0.

The same card supports app connections and credentials, Space secrets, secret
access and a computer's harness sign-in. Each control comes from that setting's
own configuration; only the Space administrator or computer owner authorized
to change it can do so. Sensitive values go to their credential store, never
into the conversation. Plain configuration can be read back by its writers,
and an Agent can suggest a value for a person to save.

Once every requested setting is confirmed on the card, the Agent that asked
receives one reply and can continue. A stopped read can run again after its
setting is checked. Service-written request cards now arrive live without
reloading. App Store Connect's web session is confirmed by a call that actually
needs it, so a working API key no longer hides an expired browser sign-in.

## Format a Page selection

Select text to apply or remove Bold, Italic, Code, Link or Strikethrough from
its menu. Selecting text keeps the editing caret in the Page; choose Comment
when you want the comment box. Mouse, keyboard and touch selections follow
the same behavior, and existing formatting shortcuts still work.

## Start Agents with less waiting

Provider quota reads run alongside Agent startup instead of delaying the first
turn. Idle Codex Instances no longer poll quota every minute. The Agents page
asks when opened or brought back into view and shows readings as they arrive,
rather than repeatedly asking while left open.

A summon refused for used-up quota requests a fresh reading. When that or a
later reading shows capacity, the waiting summon is checked again and can
start without another mention. Several refusals sharing a quota pool share
one read. A stopped Instance still needs its author's recovery choice. Older
daemons can return a cached reading; update the CLI/daemon for fresh probes.

Agents that quit before opening a session now report that they cannot take
work instead of being repeatedly selected. A sign-in retry that waits for an
uncompleted browser login ends with a sign-in requirement after 20 seconds.

## Fixes and improvements

- Follow-up messages wait for the Agent already being started, avoiding another
  picker or competing startup choices before its Run exists.
- Reconnecting daemons discard snapshots queued on the old connection and send
  a fresh snapshot, avoiding stale reports after reconnect.
- On phones, dock tabs begin moving at the tap and finish rendering when the
  transition lands; conversation navigation waits for its new screen to paint.
- Notifications name referenced Pages by their titles. Credit balances display
  in whole credits, and update provenance names the actual publication workflow.
- Retryable app-command failures retain the service's retry answer. Database
  failures retain more bounded diagnostic evidence without exposing SQL or
  credentials; these diagnostics do not claim to fix all lock contention.
- The built-in Agent launch guidance includes settings cards while staying
  within its existing compact prompt budget, including standalone and older-Hub
  launches.
- The CLI includes the panic-safe block-buffer dependency patch. Hash formats
  and stored data are unchanged; no affected application callback was identified.

## Compatibility and remaining limits

This release updates Web, CLI/daemon and Desktop. Update the CLI/daemon or
Desktop, then restart or reborn running Agents to receive the new launch
guidance. Existing app connections, Page contents and command permissions
remain in place. The mobile Web improvements also reach installed app shells
that load the stable Web; this release does not replace the queued iOS 2.2.0
App Review submission or publish a new Android package. The iOS 120 Hz switch
still requires a newer native build and is not included here.

Settings cards currently wait on the requesting Run's owner. If a setting is
changed elsewhere, reopen its card to settle it and wake the Agent. File-upload
controls and a person's `/settings` command are not available yet. The older
secret and harness request commands keep their existing cards; use
`xmatrix settings ask` for the unified card.
