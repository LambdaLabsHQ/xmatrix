# xMatrix 4.0.0

Agent mentions now start work only when the sender explicitly asks. This
release also adds approval-based sending of saved Gmail drafts, stops system
messages spending Free writes, and makes reloading and reading conversations
quieter and faster.

## Starting an Agent is explicit

An Agent can name another Agent in a report without accidentally starting it.
Ordinary `xmatrix send` messages and live Agent replies leave launch mentions
as mentions. The mention shows that nothing started, and its author can press
**Start**. xMatrix no longer asks a model to guess whether the mention is a
request.

**Update scripts that use send to start Agents:** use
`xmatrix send <channel> --launch "@codex repo:owner/repo <task>"`.
MCP callers use `send_message`'s `launch` parameter. The existing
`launch:force` condition after a mention also explicitly requests a start.
Update the CLI/daemon together; a daemon too old to carry the new option
refuses it and asks for an update.

Messages sent from the Web composer, the CLI's interactive chat and Page
schedule lines already request starts. Stop, reborn, handoff and messages to
an existing Instance keep their existing behavior. Starting an Agent still
requires the same access, computer availability and quota. This change to
send's default is why this is a major release.

## Send a saved Gmail draft after approval

Use `@gmail:drafts:*` to list saved drafts, then
`@gmail:send_draft:<draft id>` to send one with its attachments. The approval
card identifies the sender, recipients, subject, text and every attachment.
Sending uses the checked snapshot; editing the draft after approval causes a
refusal. The existing Gmail grant is sufficient; no reconnect is required.

Large approved drafts are handed to the provider through a short-lived link
instead of an inline request that the provider proxy rejects as too large.
The staged copy expires within ten minutes and is removed when sending ends.
Provider acceptance and delivery remain subject to Gmail's limits. The new
large-draft path has automated boundary coverage; a successful real send with
large attachments has not yet been confirmed and is not promised here.

An automatic Gmail read failure now preserves its failing step and bounded
technical diagnosis, without putting private mail in diagnostics. The
notification still offers a manual read. This improves investigation; the
original automatic-read 502's underlying cause remains unconfirmed.

## Free writes and Web improvements

- xMatrix's own welcome steps and automatic first-message summons no longer
  consume a Free Space's 500 writes. Previously counted writes stay counted;
  paid credits are unchanged.
- Reloading or opening a direct link to a conversation or Space view uses the
  prerendered startup page, removing the wait for the server to render that
  frame. Loading the account's actual content still requires a connection.
- Once an Agent is connected, the welcome simply says it is in and can be
  mentioned. The four starter cards are removed. A Space without GitHub gets
  a clearer connection prompt; co-writing from a Page remains available.
- Conversation dividers and phone sender labels are quieter. Reply references
  fit on one grey line. Jumping to a message fetched from older history centres
  it reliably instead of leaving it partly above the visible area.

## Updating and known limits

This release updates Web, CLI/daemon and Desktop. Refresh the website or reopen
the app for Web changes; update CLI/daemon and normally reborn existing Agent
Instances for current runtime guidance. Accounts and saved content need no
migration. iOS and Android native packages are unchanged; installed stable
shells receive the updated stable Web. User-opened release notes remain
available; no additional automatic notes popup is enabled.

The original Mac full-screen sign-in and Windows daemon-detection fixes still
await acceptance on the affected computers, and physical iOS acceptance of
connected conversation navigation remains open. Existing settings-card limits
from 3.1.0 remain. Out-of-order presence snapshots can temporarily omit an
Agent avatar without stopping its Run. Paginated App Store Connect collections
can omit later-page items or incorrectly reject a named item; large listings
and default submissions are not proof of a complete set. Underlying database
lock contention is not claimed as resolved.
