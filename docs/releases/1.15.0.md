# xMatrix 1.15.0

Connect Google Calendar, choose one permission for each connected app, and
continue Page discussions in the conversation already doing the work. This
release also helps Agent Runs reconnect after a computer wakes from sleep.

## Google Calendar

Connect Calendar separately from Drive and other Google apps. Read calendars,
find events within a time interval, check availability, and create, edit or
delete events. Existing Google connections do not gain Calendar access.

Event approvals show the proposed calendar, times, guests, notifications and
recurring-series impact. Updates and deletions check the event's exact version
so a concurrent edit is refused rather than overwritten. Uncertain writes are
not automatically replayed. Notification options retain Google's meaning:
external-only means guests who do not use Google Calendar. Repeat rules show
their complete original when a faithful plain-language summary is unavailable.

The privacy policy now explains Calendar permissions, event data and guest
notifications. Google consent and any required account authorization remain
necessary; this release does not claim Google verification has been approved.

## One permission for each app

Each Space connection has one setting: Read only, Ask first, or Read and write.
It applies in every conversation. Calendar defaults to Read and write; Gmail,
Google Ads, X and Linear default to Ask first. Review the connection's setting
before asking an Agent to change external data.

The former per-action and per-Channel rules have been retired. Old API policy
bodies are rejected instead of being interpreted as a broader permission.

## Conversations and clearer guidance

Page comments addressed to a live Agent continue in that Instance's existing
conversation. Without one, an unambiguous existing editing conversation is
reused. An unavailable existing destination reports an error instead of silently
creating a replacement. Explicit requests for another Agent can still start a
new discussion.

The @ menu explains what choosing each row does, keeps Agent descriptions in
one place, and removes redundant labels. Welcome text no longer calls a
signed-out Agent connected, and provider quota messages explain that the
provider account limit requires another Agent or a resend after it resets.
Google authorization failures distinguish a company-session reauthentication
requirement from an expired or revoked grant without exposing private details.

## Agent Runs after sleep

CLI/daemon and the Desktop app's bundled CLI now judge credential freshness
against wall time. After a long sleep, initial registration can refresh a
refused Run credential and retry once. Revoked authority and repeated refusals
still fail. Update the CLI/daemon or Desktop and restart or reborn an existing
Agent Instance to use the updated wrapper; a daemon update cannot replace code
already running in an older wrapper.

## Updating and remaining limits

Reload the Web for its changes. CLI/daemon and Desktop binaries advance to
1.15.0; Android remains 1.2.0 and stable iOS remains 1.11.1. No client data
migration is required. Existing Google events and Run grants are preserved.

Actual computer sleep recovery still needs physical macOS acceptance; automated
broker and socket checks cover credential recovery and the one-retry limit.
Historical database stalls now retain more bounded diagnostic evidence, but
their underlying cause is not declared fixed. Short stalls while loading older
messages, historical browser failures lacking traces, dedicated-identity
onboarding, physical-device and isolated multi-party or payment checks remain
separate investigations or verification gaps.
