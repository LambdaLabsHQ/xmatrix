# xMatrix 1.12.0

This release updates the stable Web, CLI/daemon and Desktop app. It brings
Windows installation fixes into both the downloadable CLI and the matching
CLI bundled with Desktop; updating the Web alone does not update either
binary. Android and iOS binaries are unchanged.

## Windows installation and the Desktop bundle

- Desktop ships a CLI seed from this same release. Its background task is
  registered for the current user's logon rather than every user's logon,
  avoiding the unnecessary administrator requirement for that trigger.
- Installing over a running `xmatrix.exe` moves the old image aside before
  publishing the validated replacement. This fixes Windows sharing and lock
  errors; a failed replacement restores the previous image.
- Scheduled-task failures preserve UTF-8 text, including Chinese paths and
  error messages, rather than replacing characters with unreadable symbols.
- Desktop loads the Web of its release channel. Stable builds use
  `https://xmatrix.sh/app`; beta builds use the separate beta Web. Native
  navigation and bridge access stay restricted to the build's trusted Web.

## Installation without changing the connection

- The Unix installer accepts `--binary-only`, PowerShell accepts `-BinaryOnly`,
  and both accept `XMATRIX_INSTALL_BINARY_ONLY=1`. This mode verifies and
  installs the binary without changing PATH, signing in, touching daemon
  services or tasks, or stopping processes. It cannot be combined with
  connection setup. Normal Human installation is unchanged.
- Agent Runs now refuse `setup daemon` and `setup install --daemon` before
  reading Profiles or changing the installation. The owner completes machine
  connection setup in their own terminal; a Run cannot switch its identity
  through installation setup.

## Page reminders and clearer Agent calls

- A Page can have a one-time reminder at a future time with an explicit
  timezone offset. When delivered, it waits on its author, appears in
  **Needs you**, and becomes done. Giving it a new time arms it again.
  Completed reminders retain the time they ran.
- Agents that write a dated commitment requiring a person's action into a
  Page are instructed to add a reminder for that action. This is guidance for
  newly launched Runs, rather than a guarantee of model compliance.
- The Page `@` menu distinguishes same-named live Instances by conversation,
  shows busy ones and lists free ones first. The saved call names its chosen
  conversation so another Instance does not mistake it for its own.
- The caller can follow Sent, Queued, Working and reply or failure outcomes
  from the call chip and open the reply. Other readers can see the chosen
  conversation and live presence too.

## Native Agent controls and connected apps

- Claude model and effort controls come from native capability discovery,
  including workflow modes such as Ultracode when the installed harness
  advertises them. Native command inventories also control which passthrough
  commands are offered; absent commands are not restored from documentation.
- A disconnected credential-based app can reconnect using its saved
  credentials. App Store Connect can list subscriptions and submit eligible
  products for review; unknown or unready named products are rejected before
  any write. Review submission does not mean Apple has approved a product.
- Bare preformatted scroll boxes no longer clip their first glyph behind
  rounded corners. The public site's comparison section reads in a simpler
  paper layout beside its alternative.

## Upgrade actions and known limits

- Update Desktop and the CLI/daemon to receive the native fixes. Existing
  Instances need a restart or reborn to use the new runtime and discovery
  behavior. Updating only the hosted Web leaves installed binaries unchanged.
- Missing native discovery leaves parameter controls unavailable while
  ordinary work may continue; older harnesses lose guessed controls. Explicit
  unsupported parameter requests still fail.
- Installation restrictions imposed by Windows policy or IT administration
  can still require the owner's action. Running-image replacement does not
  grant service permissions.
- No client data migration is required. The shared service already carries
  the Page reminder and bounded-read changes; improved failed-session
  diagnostics do not establish or fix the underlying database transport stall.
- Native device notifications, full Provider sign-in and the first-machine
  onboarding chain retain their separate real-device and dedicated-identity
  verification needs. Binary-only installation does not establish a new
  Profile, authorize a machine or configure a Provider.
