# xMatrix 4.2.0

Pages can carry Norn programs: work that repeats, waits for a time or an
outside event, asks an Agent or a person, and shows what it will do next.
This update is the website and the CLI/daemon; the Hub already runs the
programs. The Desktop app stays on 4.0.0, the Android app on 4.1.0 (still in
Google Play review), and iOS on 4.0.4.

## Norn programs

A top-level `norn run` block on a Page is a program. The word after the tag
names it, and a block without one is `main`. Adding a block starts it, editing
the block revises the same program without asking its past requests again, and
removing it stops the program. Each block gets one conversation for its life,
and its requests and result are posted there.

A program can:

- wait for a date or a beat: `after(<UTC time>)`, `every(1d)`, and
  `every(7d, ~from=2026-11-16T09:00Z)` to keep a weekday and time;
- hear outside events: a failed CI run, a merged pull request, or a new Sentry
  issue;
- ask an Agent or a person, with a deadline (`~by`) and what silence means;
- say something in its conversation, including a dated reminder to a person;
- open the standard library with `open Std`, where `routine(...)` repeats a
  task, falls back to another Agent, and takes a default when nobody answers.

The Page draws each program's state and flow: what it waits for now, what
follows, and the branches for each way a request can end. A block that does not
check says why, with the place marked in the code. `xmatrix page read` prints a
`programs:` section, and `xmatrix page edit` names every block that does not
run as written and why.

Agents are taught to write programs for recurring, dated and event-driven work
instead of separate schedules.

## Asking a person

An Agent blocked on a person can ask with `xmatrix confirm`, `xmatrix choose`
or `xmatrix ask`, with `--by` (a duration or a UTC time) and `--otherwise` (the
answer taken when the deadline passes). The question is posted as a card in the
conversation, the person answers on the card, and the Agent wakes with the
answer. A message names a request by what it asks, not by an opaque reference.

## Billing

Settings → Billing now itemizes the Space's usage: one row per Agent, app and
person's paid X calls, with messages and page edits counted separately. Each
member sees their own share under "You and your Agents", and "How credits are
counted" explains the rules. A waived operator Space shows the real use marked
"not charged". The Billing screen inside the iOS and Android apps shows the
same usage.

## Apps and connectors

- A Stripe notification reads as words in the Space's language, with the amount
  and a link to the payment; older Stripe messages already in a Channel draw as
  the same card.
- Reading Google Play Console tracks no longer opens an edit, so it cannot
  delete an upload in progress. A used-up Google quota is named as a quota, not
  a permission problem.
- The privacy policy discloses what the Google Play Console connection reads and
  changes.

## Web and CLI

- A deleted Channel now leaves the address bar, its history and its cache.
- Ctrl/⌘+F on a Page searches that page, with a match count and next/previous.
- Code is drawn in the bundled Cascadia Code font, so `->` and `=>` form one
  sign; Norn dates and times are drawn as one token.
- A delivered request is shown as readable paragraphs, and a `request:<ref>`
  reads as the question with its state instead of its reference.
- If sign-in succeeds but the session is still empty, the reason is named; an
  early script error now reports where it fired.
- On Windows, text flattened to `?` by a non-UTF-8 writer is refused from
  arguments, stdin and files, including Hub commands such as `xmatrix reply`.
  The refusal names the correct PowerShell UTF-8 writer. Windows startup errors
  are decoded in their own code page.
- An Agent with a non-ASCII name (for example 牛马) completes its handshake.
- `xmatrix goal set` reaches its inbox inside a Claude run.

## Already live

These Hub changes need no update:

- A summon now asks the machine whether the runtime is signed in instead of
  keeping a stale copy, so a sign-in done in a terminal is honored; a refused
  summon or handoff shows the sign-in card.
- When a provider account runs out of balance, its resting Instances stay
  resting, so one exhausted account no longer wakes siblings and posts several
  failure cards.
- A network block during authentication (for example a Cloudflare 403) is not
  treated as a sign-out.
- A Run whose owner is a Space admin can tighten an existing secret to `ask`
  without changing its value.

## Compatibility and known limitations

- Norn programs run with the authority of the person who wrote the block, or of
  the owner of the Agent Run that wrote it.
- A program whose text this Hub build cannot check is deferred, not ended, so a
  program written for a newer build keeps its ledger and resumes.
- A Page with no `norn run` block fetches no program status.
