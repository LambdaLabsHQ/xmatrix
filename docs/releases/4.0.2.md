# xMatrix 4.0.2

This update is the website. Refresh it to pick the changes up. The CLI and
daemon stay on 4.0.1, and the Desktop app stays on 4.0.0. Android is
unchanged. This release does not submit a new iOS build to the App Store.

## Reading and composing

Press ↑ in an empty composer to see what you sent in this Space on this
browser, newest beside the field. ↑ and ↓ move through the list. Enter or Tab
puts the highlighted draft back so you can edit or send it. Escape, typing,
or ↓ past the newest closes the list. Pages and channels you had picked come
back picked. An Agent comes back as the `@name` you wrote, and is resolved
again when you send. The list stays on this browser, for the person who is
signed in, and holds up to 50 drafts. Picture lines are left out, because
their files went with the original message. A draft that was only pictures
is not listed.

The last message in a conversation can be scrolled clear of the Agents-at-work
card again. After Agent status moved into its own record, that card covered
the last message and the list could not scroll far enough to uncover it.

## Gmail

Clicking a Gmail message that xMatrix has read opens that message in Gmail,
in the Google account that holds its mailbox. Links and buttons inside the
card, and a click that ends a text selection, keep their own meaning.

## This browser

Input history, search history, page summon markers and the preferred writer
now stay with the signed-in person and the Space. Signing in as someone else
on the same browser no longer offers their private inputs or searches. Older
records that were saved without an owner are left unused, because their
author cannot be proved. They are not deleted and not given to another
account. A blocked or full browser store does not stop sending, searching or
calling an Agent.

## Updating and known limits

Accounts and saved content need no migration. Scripts that start Agents must
keep using the explicit launch option introduced in 4.0.0. This release does
not turn on an automatic release-notes popup.

This release does not submit iOS to App Review. The App Store build already
waiting for review stays as it is. A new submission is still waiting on an
in-app login recording.

A successful send of a large Gmail draft is still not confirmed end to end.
If removing its staged copy fails, a send the provider already accepted can
still show as an error; check the mailbox before sending again. The Mac
full-screen sign-in fix and the Windows daemon-detection fix still await
acceptance on the affected computers. Daemons that are not updated keep the
behavior they already have.
