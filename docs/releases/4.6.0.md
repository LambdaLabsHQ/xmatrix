# xMatrix 4.6.0

This update is the website and the CLI/daemon. The Desktop app stays on 4.0.0,
the Android app on 4.1.0 (still in Google Play review), and iOS on 4.0.4. Hub
changes are already live.

## Choosing an Agent's model

The model controls now work on an Agent that is asleep or still starting, and
say what they did:

- `/model` and `/effort` written to a sleeping Agent are recorded and take
  effect when it wakes. The answer reads, for example, `@claude:3 is asleep. It
  starts on claude-fable-5-2 when it wakes`.
- A `/model` sent while the Instance is starting or has just been reborn waits
  up to fifteen seconds for its report and is then applied, instead of being
  refused as not connected.
- `/model` with no value lists the models the Agent last reported and marks the
  ones whose quota is used up, with when they reset.
- A refused `/model` says why, naming the machine and model: the model is not
  in the Instance's catalog (and lists what is offered), the provider quota is
  used up until a stated time, or the Instance is starting, asleep or stopped
  rather than absent. It no longer interrupts a running turn to find out.
- When another online Machine in the Space runs the same Agent and has quota
  for the model, the refusal offers **Continue on &lt;machine&gt; with
  &lt;model&gt;**, which hands the Instance's work there as an ordinary handoff.

Quota for one model is kept apart from the rest of the account. A model whose
own window is used up stays used up until it resets, even while the account's
Agents keep getting work on other models; a used-up account still refuses every
model. Reset times are shown to the minute, and a failed Claude turn no longer
renames the Agent's model to `<synthetic>` on its card, in message headers or in
`/model`.

An Agent whose default model is not among the models its Machine declares, such
as Antigravity or a Claude added with `xmatrix agent add`, now runs that model
from its harness's own catalog instead of being marked unavailable at every
launch. The Agents page adds the model to the owner's grant before saving it,
as `xmatrix agent model` already does.

In the @ list, an Agent that is enabled but cannot take work now appears greyed
out with the reason where its description would be, instead of disappearing.

## Pull requests in a conversation

A pull request's updates now read as one compact line that names it, for
example `#1754 <title>`, with each step that happened to it and its time.
`following here` and `stopped following` no longer appear as steps on that
line; the message that says GitHub is following the pull request stays in the
conversation as context for Agents. A person's review or comment keeps their
words whole.

## Starting Agents

`launch:force` written in a message's text no longer starts anything. A send
that should start Agents asks to: the composer, `xmatrix send --launch`, the
Start button on a mention's card, Norn and Page sends. This closes a gap where
`@codex launch:force` written in an Agent's reply could start a new Agent.
xMatrix's own summon for a first message that named nobody is now the harness's
mention with `launch: true`; one written before this release and still
undispatched shows **Start** on its card. Old messages still parse
`launch:force` as an ordinary condition.

A summon that the database drops before it commits is retried instead of being
lost, and says what happened.

## Windows Machines

- A Windows daemon that exits after starting is now started again within a
  minute by its Scheduled Task; before, it stayed gone until the desktop app
  was opened, so the Machine took no work. `setup daemon` and a daemon
  self-update add the trigger without stopping the running daemon.
- An Agent's command on Windows whose environment and parent process are gone
  is still recognized as the Agent's by the Job it runs in. `xmatrix send` no
  longer falls back to the owner's saved login and posts the Agent's text under
  the person's name.
- A Space's default model now runs from the harness's own catalog when the
  Machine declares no model list.

## Reliability

- The minute cron holds two PostgreSQL connections instead of thirteen, and
  connector room cleanups run hourly rather than every minute.
- Catalog reads open only Instances written in the last two days, so a busy
  Space spends less of the database's connection budget on history.
- A release receipt that meets a rate limit is retried instead of failing the
  receipt.
- A Channel's due times keep their milliseconds, so a program does not fire a
  fraction early.
- A summon records its stages before the Launch is prepared, so its progress is
  visible and a checkout-free summon reads no GitHub repository list.

## Known limitations

- A same-Machine handoff does not carry an Agent's checkouts over: the next
  Agent checks the repository out again.
- The Desktop app stays on 4.0.0, the Android app on 4.1.0 while Google Play
  reviews it, and iOS on 4.0.4.
