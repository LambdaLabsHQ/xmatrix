# xMatrix 1.14.1

This Web patch keeps query-backed screens and their actions aligned after a
sign-in change, sends messages without waiting for mention previews, and fixes
Page links and routine stop feedback.

## Pins and screens follow the current sign-in

When the browser changes its signed-in account, query-backed screens now
reinitialize with that account's query client. Previously, a screen could keep
showing a pin through an older observer while an action read a new empty
cache, causing Unpin to save the pin again. Removing the last pin now saves
an empty list in this flow. An unchanged sign-in keeps its existing client
and mounted state.

## Send without waiting for a mention preview

Enter and Send no longer wait for an Agent-routing preview or its timeout.
They use only completed readings for the exact current draft; an unfinished
preview goes through the existing server check after the message is posted.
Old draft readings remain excluded, and launch authorization is unchanged.

## Follow Page links with a click or tap

Ordinary clicks and phone taps now open bare URLs and Markdown links from an
editable Page, keeping the Page in its own tab. Drag selection, address
editing and continued writing retain their behavior. Executable or unsupported
link protocols remain blocked.

## Routine stops keep their feedback in place

A successful stop through the interface updates the existing Instance and
invocation state without adding another routine confirmation message.
Historical typed routine confirmations are also hidden in the Web. Stop
failures, failed-startup cleanup, access withdrawal and Instance deletion keep
their explanations; stored Channel history is unchanged.

## Update and verification limits

Reload the Web to receive the changes. Desktop uses the updated hosted Web;
no client reinstall or data migration is needed. CLI/daemon and Desktop
binaries remain at 1.12.0, Android at 1.2.0 and stable iOS at 1.11.1.

Short stalls while loading older Channel history remain a separate performance
investigation. Dedicated-identity sign-in, first-machine onboarding,
physical-device and isolated multi-party or payment verification requirements
remain open.
