# xMatrix 4.0.6

An Agent's model tag shows the name its harness gives that model, and a
page is always the page as it is now. This update is the website and the
CLI/daemon. The Desktop app stays on 4.0.0. Android is unchanged. This
release does not submit a new iOS build, and it does not change an App
Review outcome.

## Model names

The model tag used to show the id the harness selects with. DeepSeek
Harness selects with a JSON pair such as
`["deepseek-official","deepseek-flash"]`, so the tag was cut off at the
provider and never reached the model. The tag now shows the name from
that harness's own catalog, `DeepSeek-V4.1-Flash`, on the Agent card and
in message headers. A harness that lists no name still shows the id.
Cursor's `composer-2.5` shows as Composer 2.5. The id used to switch
models is unchanged.

Models a harness lists in groups, as DeepSeek does per provider, now
appear in the model switcher. Update the CLI and daemon together, then
restart the Agent, before the new name replaces the old tag.

## Pages and conversations

A page is always its newest version, with nothing marked in the text.
History is where changes are marked, and it opens on what changed since
your last visit. A block that was mostly kept is marked word by word. A
block rewritten past recognition shows the old text struck out and the
new text whole. A table keeps its rows and columns. Opening a page from
a message's edit card opens the page as it is now.

Read now means visited: the newest version you have had open. The page
no longer times which blocks were on screen.

The details rail lists the conversation's Agents again. A mention of an
Agent on an offline computer says why it is waiting. The cards beside a
page show which Agents are live in each linked conversation.

A quote above a reply, a quoted passage, and the quote slip in the
composer each open with a large quotation mark.

## Gmail

`@gmail:send` and `@gmail:reply` send the files attached to the command,
up to 20 files and 25 MiB. The approval card lists each file's name and
size. The send reads those files again and refuses one whose content,
type, or version changed after approval. The existing Gmail grant is
enough; no reconnect is required.

A paperclip attachment is no longer counted as an inline image just
because it has a Content-ID. A part is inline only when it says so, or
when it has a Content-ID and no disposition, as a signature logo does.

## Starting an Agent, and talking to one

A CLI or MCP send that would start an Agent, but names no Instance and
does not pass `--launch` (MCP `launch: true`), is now refused before it
is published. Address an existing Instance with `@<agent>:<instance>`,
or pass `--launch`. The website composer already requests a start.
`launch:force` written in the message text does not.

With no model list on the registration, a summon can name a model from
the runtime's own catalog, the same set a live model switch offers. A
written `model:` matches the id or a name the runtime lists, such as
Claude's `opus` or `Sonnet 5.5`. The runtime's default is unchanged
unless the author or the discussion names another model. A daemon that
does not advertise this yet still refuses a written model. Update the
daemon with the CLI.

A slash menu no longer stops at 64 commands, and a runtime with a long
parameter list is no longer rejected whole. Model, command, and
parameter menus keep what the runtime advertised. An open connection
fills those lists in on its next presence update or reconnect.

An Agent whose harness does not accept inline images, including DeepSeek
Harness, no longer fails the whole turn when a message contains a
picture. It receives the text, which already names each picture's local
copy. A launch whose harness program is missing is refused by name,
with how to install it, before the run starts.

On the website, a signed-in Desktop app that can install its own CLI and
finds none now receives a CLI session and starts the daemon.

## The CLI

`xmatrix send --file` (`-f`) reads the message body from a UTF-8 file.
`--attachment` attaches a file beside the body. A send with attachments
and no body is refused, and so is `--file` next to another body.

**Scripts that attached a file with `--file` must use `--attachment`.**

## Windows

`xmatrix setup daemon` turns on Windows long paths before it starts the
daemon. Without an administrator prompt it prints the exact command to
run. Git used by an Agent has long paths on. New sessions start in the
short checkout pool, so a deep `node_modules` tree can start. Sessions
already in an older pool stay there; nothing is moved or deleted.

Windows still does not start a program from a folder or an executable
path longer than 260 characters. An Agent whose workspace folder is past
that limit fails with the folder and its length.

## Updating and known limits

Refresh the website, and install the CLI and daemon update together, to
pick this up. Restart an Agent after the CLI update so its model tag
uses the catalog name. Desktop stays on 4.0.0, so the Desktop app's own
display of a deep checkout is unchanged. Android is unchanged. Accounts
and saved content need no migration.

A successful send of a large Gmail draft is still not confirmed end to
end. If removing its staged copy fails, a send the provider already
accepted can still show as an error; check the mailbox before sending
again.

An App Store Connect change that adds members to an existing
relationship reads the full current membership first, and refuses the
plan when that read is incomplete. Refresh such a plan before approving
it again. Relationship plans made before this behavior do not carry
that check.
