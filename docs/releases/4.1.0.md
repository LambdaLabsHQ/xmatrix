# xMatrix 4.1.0

The Android app is ready for Google Play, and sells Pro through Google
Play. A message takes any number of files, and a summon can name a model
again. This update is the website, the CLI/daemon and the Android app.
The Desktop app stays on 4.0.0. This release does not submit a new iOS
build, and it does not change an App Review outcome.

## Android

The stable Android app loads and trusts only `xmatrix.sh`, and signs in
through the xMatrix Hub. It is the build intended for the Google Play
listing; the previous stable Android app was 1.2.0.

Pro is bought inside the app through Google Play Billing. Settings →
Billing in the Android app shows a Google Play section with the monthly
and annual Pro plans, and never offers card checkout or credit packs.
A purchase is confirmed with Google before Pro turns on, and renewals,
cancellations and refunds that Google reports update the Space's plan.
A Google Play subscription is managed in Google Play; the card billing
portal does not open it. Like an App Store subscription, it covers one
seat and ends at the end of the period Google reports.

Other changes since 1.2.0:

- Back on every phone screen returns to that screen's parent, not
  through the browsing history.
- When the server answers with an error page, the app opens its own
  packaged copy of the workspace instead.

## Messages and attachments

A message takes any number of files. A new, empty message could refuse
attachments with "Attach at most 10 files" after files sent earlier in
the same conversation; that limit is gone in the website composer and
in `xmatrix send --attachment`, which allowed 4. Each file still has its
own size limit, and uploads run three at a time.

A fenced code block tagged `norn` is highlighted in messages and on
pages, and its label reads "Norn".

## Agents

A summon can name a model again. 4.0.6 let a summon pick a model from
the runtime's own catalog, but the daemon never told the Hub it could,
so the `@` menu offered no `model:` rows and `@claude model:sonnet` was
still refused. The daemon now reports it. Once a Machine's daemon runs
4.1.0, the `@` menu lists each runtime's models after its name, and a
written `model:` matches the id or a name the runtime gives it, such as
Claude's `opus` or `Sonnet 5.5`.

`@<agent>:<n>:stop`, `:reborn` and `:handoff:` that address no Instance,
such as a mistyped name or a full Instance id in place of the Channel's
number, used to leave their refusal only on the message. `xmatrix send`
now exits with an error that says the message was sent, quotes each
refusal and shows the form to resend, as in `@deepseek:3:reborn`.

An Agent whose provider account has run out of prepaid balance, such as
DeepSeek's "Insufficient Balance", is treated like one that reached its
usage limit: the turn is handed to another Agent you have on that
Machine, and the card says to top up the account.

## Apps

`xmatrix connector list` labels an action that runs only as a Channel
message, such as `@github:subscribe`, as `send`, and `xmatrix call` on
one says to send it with `xmatrix send`.

After **Check again** fails on an app's page, the reason is shown once.

## Already live

These were Hub changes and need no update:

- Connect with X reaches X's consent screen again; every connect had
  ended on "You weren't able to give access to the App".
- The Google Play Console app connects with one sign-in and lets Agents
  read and update tracks, releases and subscription base plans.
- A GitHub refusal names the repository and says who links the account,
  with a card to reconnect when that fixes it.
- An Agent's own approved connector receipt no longer refuses its next
  send.

## Updating and known limits

Refresh the website, install the CLI update (the daemon restarts on
it), and update the Android app. Model rows appear for a Machine once
its daemon is on 4.1.0. Accounts and saved content need no migration.

A connect started in the Desktop app still finishes in the browser;
returning to the app needs a Desktop update that is not part of this
release.

Google Play purchases have not yet been completed end to end with a
test account, and the app is not yet published on Google Play's
production track.
