# xMatrix 4.14.0

This release updates the website (`4.14.0`, from `4.13.0`, serving `xmatrix.page` and `xmatrix.sh`) and CLI and daemon (`4.14.0`, from `4.13.0`). Desktop (`4.9.1`), Android (`4.6.2`), and iOS (`4.11.0`) keep their current versions. Hub and connector updates below are already live.

## Website

- **The public site says only what xMatrix actually does.** Every public page was checked against the product in all six languages and corrected where it overstated or misdescribed it:
  - Pricing now states the price and the credit rule plainly: Agent and app messages and Agent Page revisions use credits, people write for free, and extra credits are $10 per 5,000. Pro no longer lists approvals, connectors or context relay as Pro-only, because every plan has them.
  - Claims about credentials, approvals and co-editing now match how they work: Runs receive short-lived tokens and injected secrets, "Ask first" is a per-connection setting chosen by a Space admin, and a co-writing Agent stays out of the paragraph you are editing rather than waiting for you.
  - A Space holds a tree of Pages that Agents keep current as work lands; the site no longer promises one document per project that updates itself.
  - Comparison pages are titled "<Name> vs xMatrix" and no longer show a breadcrumb, an eyebrow label or a "Verified" line. Their facts were corrected (40+ connectors, iPhone and iPad as a native app, secrets, approvals) and they no longer criticise other products' defaults.
  - The CLI guide and its translations were corrected, including that `xmatrix send` needs `--launch` to start an Agent, `agent add --access`, and trace retention (5,000 events, 16 MiB, 24 hours, also stated in the privacy policy).
- **Footer comparisons list direct competitors.** The footer now reads "Compare xMatrix with" followed by Raft, Lody, Multica, Paradev, Conductor, LobeHub, Notion, Orca, T3 Code and Cumora. The Claude Code comparison page is retired (Claude Code is a harness xMatrix runs) and its address redirects to the supported agents documentation.
- **Summon conditions complete from a value.** After the first condition in a summon, typing a bare value such as a machine or repository name now offers matching conditions; you no longer have to type the key (`machine:`) first.

## CLI and daemon

- **`xmatrix channel subscribe --wait`.** An Agent can subscribe a conversation to a GitHub workflow run or pull request and wait for its report inside its own harness, so it shows as waiting instead of idle. The wait returns when the run's verdict or the pull request's next CI result, review, comment or merge arrives (`--timeout <minutes>`, default 60), exits non-zero on a failed run or timeout, and reads only the conversation, never GitHub. The subscription stays on the Hub, so the report still wakes the Agent if the wait ends early.
- **Long waits renew their credential.** A `subscribe --wait` that outlives the Agent Run token asks the daemon for a fresh one and keeps going instead of failing every check until its timeout.

## Hub and connectors (already live)

- **Google Docs, Drive and Sheets writes use Google's Workspace MCP.** Listing files, creating Docs and Sheets, appending to a Doc and updating a Sheet now go through Google's Workspace MCP. Sheet cells keep their literal text (a value like `=1+1` or `01` is stored as typed), and a write is never applied twice when falling back.
- **Switching a connector account works again.** Switching an OAuth connector such as Google to another account no longer fails after a Check has recorded the connected account.
- **Connector commands that create something are not mistaken for Agent launches.** `@google:create_doc:new` and similar commands no longer also post a notice about retired launch suffixes.
- **Agent registrations from retired harnesses no longer break settings.** Spaces that still hold a ZCode registration can list their Agent registrations again; ZCode itself stays refused.

## Compatibility and updating

- Run `xmatrix update` on each machine to update CLI and daemon from `4.13.0` to `4.14.0`. No manual migration is needed.
- Refresh the web app to pick up `4.14.0`. The live Hub already supports this release.

## Known limitations

- Windows CLI binaries are not yet Authenticode-signed.
- Desktop (`4.9.1`), Android (`4.6.2`), and iOS (`4.11.0`) are unchanged in this release.
