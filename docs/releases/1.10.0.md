# xMatrix 1.10.0

Changes since 1.9.0. This release updates the stable Web. It adds ways to work
with an Agent already on a Page and to read connected apps privately, and fixes
file previews, phone navigation and sign-in verification.

## Work with an Agent already on a Page

- A Page's `@` menu offers live Agent Instances in that Page's conversations.
  Call one there instead of starting another Instance.
- The call shows **Sent** after the message is saved and **Started** when the
  Instance begins handling it, instead of staying on **Sending**.

## Read connected apps privately

- `xmatrix call "<read command>" --public` returns a connected app's result and
  shares it in the Channel. `--private` returns the original only to the caller
  and masks the result in Channel receipts and execution history.
- Both modes record the invocation and its parameters in the Channel. Keep
  credentials and other private values out of those parameters. Private reads
  use the same access and connected-account checks as ordinary reads.
- Writes continue through `xmatrix send` and the Channel's approval policy.
  These read commands come from the Hub; no CLI update is needed this time.

## Fixes and improvements

- A Markdown file opens immediately after you upload and send it. You can also
  preview it while its upload is still in progress, without refreshing.
- On a phone, Back follows the current screen's parent: conversation to its
  Space's list, conversation details to the conversation, and a Page's
  conversation to the Page. Open sheets and dialogs close first.
- A previously admitted Web build can start while its compatibility check runs
  in the background, reducing repeated preparation screens. A refused build
  still shows the upgrade requirement.
- Failed Agent launches show as **couldn't start**. New offline-machine notices
  name the computer, explain how its owner can reconnect it, and offer the
  summon's author **Send again** once it is online. Retrying checks access and
  availability again; it does not reserve or queue a launch.
- An app sign-in waiting for an authenticator or backup code stays on that step
  even if the browser already has a website session. Starting over signs out
  and abandons that app handoff.
- Repository choices begin loading when you open the Space, so the project
  picker can show its cached choices immediately and refresh after GitHub
  connection changes.

## Compatibility and upgrade

- Reload the stable Web to receive these changes. No CLI/daemon update,
  native-shell installation or account migration is required for this release.
- Desktop, Android and iOS native shells are not rebuilt or promoted here.
  Their hosted stable Web receives the interface changes.
- The shared Hub already serves the connected-app reads and improved Agent
  delivery. It continues serving older clients through their existing paths.

## Known limitations

- The new iOS edge gesture and native in-page notification/deep-link handling
  require newer native shells. Existing iOS builds retain their WebKit gesture;
  this Web release does not update it. Use the on-screen Back control.
- Older offline-machine notices without the new details retain their text.
- Private reads mask the result, not the invocation or its parameters.
- A lost confirmation of a Page call can still need a refresh to establish its
  outcome. Long-history co-writing recovery and device-level sign-in and
  navigation checks remain separate work.
