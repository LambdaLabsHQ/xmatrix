# xMatrix 4.5.0

This update is the website and the CLI/daemon. The Desktop app stays on 4.0.0,
the Android app on 4.1.0 (still in Google Play review), and iOS on 4.0.4. Hub
changes are already live.

## Agents check out the repositories they need

An Agent you summon without `repo:` no longer has to be given a repository up
front. It starts in its own xMatrix-managed working directory, reads the task,
and checks out the repositories the work needs with
`xmatrix repo checkout <owner/repo>`, which prints the path of its own
worktree. Asking again returns the same tree, and the Agent's next Run in the
same conversation takes it back after a restart. Pushes and GitHub calls from
that worktree use the Space's GitHub connection, as before. Naming `repo:` in a
summon still checks the repository out at launch.

The daemon needs 4.5.0 for this. A Machine on an older daemon keeps choosing the
repository when the Agent is launched.

## An Agent can set its owner's default model

`xmatrix agent model <harness> [<model>|--clear]` shows or sets the model an
Agent runs when a launch names none, the same value as **Default model** on the
Agents page. An Agent can run it for its owner's Agents in its own Space, so a
conversation can ask an Agent to move a harness off a model that has no
capacity. It changes only the model: if the owner's grant does not list that
model yet, it is added; nothing else about the Agent or the grant can change
this way, and a change someone made in between is refused, not overwritten.

## Pull requests in a conversation

What GitHub reports about a pull request an Agent opened (CI passed or failed,
merged, closed) now reads as one compact line per pull request, with where it
stands now and each step with its time, instead of a separate full message per
event. A person's review or comment keeps their words whole. The line that says
GitHub is following a pull request in the conversation no longer counts as
unread and no longer wakes the Agents in it.

## Machines and programs

- A Machine's version row shows what its update is really doing: checking,
  installing a version, or "Not updated" with the reason and the fix. Seeing a
  Machine's CLI behind asks its daemon to check once, instead of showing an
  Update mark with nothing to act on.
- When a program on a Machine is not signed in, the card offers its owner
  **Sign in** and **Disable** side by side. Disable turns that Agent off on the
  Machine in every Space, so no more work is sent to it; the Agents page turns
  it back on.
- Antigravity receives an Agent's instructions as its own system rules, so an
  Agent with trusted instructions can now run on Antigravity.
- Choosing an Antigravity model with a level, such as
  `model:gemini-4-hydrogen-medium`, now switches to it instead of failing at
  start.
- When another Codex process on the same computer still has an Agent's
  conversation open, the Run says so once, names that process, and says to end
  it and send the message again. The conversation is kept, and later messages
  no longer post the same failure again.

## Fixes

- Typing a ` ```norn run <name>` fence on a Page keeps the program's name, so
  the block becomes a program.
- Gmail new-mail notifications no longer stop for good after a pass fails
  midway, and a long backlog no longer repeats a notification.
- Fewer short failures while the database is briefly slow.

## Known limitations

- A same-Machine handoff does not carry an Agent's checkouts over: the next
  Agent checks the repository out again.
