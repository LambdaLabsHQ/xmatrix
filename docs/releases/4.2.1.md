# xMatrix 4.2.1

This update is the website and the CLI/daemon. The Desktop app stays on
4.0.0, the Android app on 4.1.0 (still in Google Play review), and iOS on
4.0.4. Hub changes are already live.

## Adding an Agent

Adding an Agent to a machine now asks that machine's owner to confirm the
access it will run with, and spells out what full access adds. An Agent Run
cannot add a harness its owner has not confirmed, and an Agent added before
this change is marked unconfirmed until its owner confirms it. Existing Agents
keep running as they did.

Claude Code, OpenCode and Grok ACP can also be added with "ask": the Agent
starts with no standing grant, and each permission request appears as a card in
the conversation with the answers the harness offers. A plain `xmatrix` reply,
page read or message needs no card. Ask mode needs this CLI/daemon on the
machine. DeepSeek Harness and Codex are offered full access alone, because
their permission switch is part of the environment they run in.

The same rule is in the CLI: `xmatrix agent add --access full|ask`,
`xmatrix agent access <harness> [full|ask]`, the ACCESS column in
`xmatrix agent list`, and `launchAccess` in `xmatrix agent show`.

## Getting a computer ready

On a Mac or Windows browser, the first onboarding step offers the app download
for that computer (Apple Silicon, Intel or Windows) instead of a terminal
command, and explains that the app signs in with the same account; it needs no
approval step. "Use a terminal instead" still reveals the command and its
approval steps. Linux and unknown systems show the command as before, and
inside the Desktop app the step says the app is setting up this computer.

## Agents and accounts

- A DeepSeek Agent shows the money left on its API key: the Agent card, the
  Agents page (`Balance ¥12.34 left`, or `Out of balance`) and
  `xmatrix agent list`. No percentage is invented, and a missing or refused key
  still shows `-`.
- A client older than this release shows `-` for a prepaid account instead of a
  misleading `100%`.
- A DeepSeek Agent can run `xmatrix` from its own shell (`whoami`, `status`,
  `channel history`, and a reply) without raising permission for each call.
- A Cursor turn whose only reply is "Add a payment method to continue" is a
  failed turn: the Channel sees the failure, and routing stops choosing that
  account.
- A model picked from the summon menu is written by its readable name, not the
  harness's selector, so a DeepSeek pair no longer appears as
  `[""deepseek-official"",""deepseek-flash""]`.
- A question in a conversation gets a direct answer; the opening message for
  work is one sentence on what will be done and checked, not a four-field form.

## Pages and programs

- `xmatrix page read` run by an Agent now shows the page's `programs:` section;
  the Hub refused that read for an Agent Run before.
- A `norn run` block whose name runs nothing (it starts with a digit, is too
  long, or repeats another block's name) is reported with its name and reason
  by the page, `page read` and `page edit`, instead of showing `starting…`
  forever. A message carrying one is refused with the same reason.

## Reliability

- Launch reads (machine name, settings, host, fallback origin) now take one
  lock-free statement and recover once from a stalled round trip, so a brief
  database pause no longer fails a launch or its recovery.
- A handoff whose chosen Agent cannot start moves on to the next eligible
  Agent, up to three attempts, instead of leaving the work with nobody. A
  successor the author named is not replaced.
- A first Run that ends before its Agent is ready no longer leaves an Instance
  that every later message wakes into the same failure.
- An execution report the Hub can never store (its Run binding is gone, or the
  stored evidence conflicts) now gets a final receipt, so a stuck daemon outbox
  drains instead of retrying every five seconds. This is already live in the
  Hub; the daemon needs no change.
- A connector call that hits a retryable database or Durable Object outage is
  answered as retryable, not as an unexplained 500.
- A page read or Agent Launch history read that loses its database response is
  replayed once when nothing was written, instead of failing.

## Already live

These are Hub changes and need no update:

- A turn that accepts work and then makes no progress for five minutes is said
  in its conversation, with the ways to act on it.
- DeepSeek's prepaid balance is understood by routing: an account the provider
  refuses is not chosen.
- A Norn request can only be answered by a person who can still read the
  conversation.
- A hyperdrive pool fits the production database's 25 connection slots again
  after the provider's maintenance.

## Updating and known limits

Refresh the website and install the CLI update (the daemon restarts on it) to
get the new Agent access controls, the balance display, page programs for
Agents, and the launch-read recovery. Accounts and saved content need no
migration.

- Ask mode is not yet verified end to end on a real machine; it needs the
  4.2.1 CLI on that machine.
- A CLI older than 4.2.1 shows `-` for a prepaid account's balance until it
  updates.
