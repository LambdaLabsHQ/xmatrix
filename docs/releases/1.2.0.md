# xMatrix 1.2.0

Changes since 1.1.0.

## New

- Select a passage on a page and choose Discuss. That passage keeps one thread. Opening the thread from the conversation list shows the passage it is about.
- Each version has a release notes page at `https://xmatrix.sh/releases/<version>`. Desktop's update dialogs offer Release notes, and Machine version rows, CLI update output, and download cards open the same page.
- A channel's actions sit as icons after its name. Deleting a channel asks once. Move is no longer in that row.
- GitHub code scanning alerts can arrive as Channel events for agents subscribed to the repository.
- `@sentry:list_issues` lists a release's Sentry issues. A list that cannot be read is reported as unavailable instead of empty.
- Space admins can see each person's connector activity.

## Improvements

- Pages open with their discussions, and their links and conversations are read together. The browser talks to the Hub directly for a page, its conversations, and a live session ticket, and those direct requests stay cacheable.
- A claim names who else is on a section and does not lock it. People do not see or make claims. A pull request that names a page section is not held for a claim, and merging it leaves every named section owing an update.
- When an Agent's turn fails, the notice keeps the HTTP status, error code, and request id the provider actually sent, instead of a shortened message.
- An Agent started for a new conversation sees that conversation, including the question, and can answer it on the first reply.
- A timeline you have scrolled up stays put when messages arrive below. The page edge chip sits on the text. Nothing scrolls under the floating window search. A page margin card shows the sender's avatar. An empty conversation beside its page does not repeat the page name.
- Committed system notices reach people who already have the channel open. A refused automatic summon leaves a receipt. The first message in a page discussion can summon an Agent. New-mail notifications are delivered through Channel subscriptions.

## Compatibility

- The CLI no longer includes a built-in test environment or Cloudflare Access login. Production is unchanged. An older config root starts as the production profile. A custom Hub is still set with `--hub-url` or `xmatrix profile`. Desktop, Android, and iOS no longer treat `test.xmatrix.sh` as an xMatrix host, and Desktop no longer switches environments.
- Repositories that required the `xmatrix/claim` GitHub check should remove it from required checks. That check is no longer published.
- Failure details and the new conversation startup text ship in this CLI. A daemon updates itself. An Agent that is already running keeps the previous behavior until that instance is reborn.

## Known limitations

- On the App Store, 1.0.250 is still the version in review. A newer iOS version is not offered there until that review finishes.
