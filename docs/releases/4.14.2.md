# xMatrix 4.14.2

This release updates the website (`4.14.2`, from `4.14.1`, serving `xmatrix.page` and `xmatrix.sh`) and the CLI and daemon (`4.14.2`, from `4.14.0`). Desktop (`4.9.1`), Android (`4.6.2`), and iOS (`4.11.0`) keep their current versions.

## Website

- **Pages show their facts and program branches.** A Page that holds `norn 1 facts` blocks shows them as compact property chips above the document. A Page program that runs branches lists each branch with its status (running, waiting, failed, done), its latest request, and a link to that branch's own conversation.
- **Setup no longer polls in the background.** The "bring Agents in" card only creates a setup command when it actually shows one. While it waits, it checks less and less often, and it stops when the command expires instead of making a new one forever. Tabs left open no longer keep asking the server.
- **Google Play connection.** After connecting Google Play, the reports bucket syncs on its own. Settings cards that could not be completed are no longer shown.
- **Where a new account came from.** When an account is created, xMatrix records once the domain of the site that sent you (for example `x.com`, or `direct`) and the link's campaign tag. It never records the full address and stores nothing on your device for this. The Privacy Policy describes this.
- **Chrome extension approvals.** Opening an approval card from a Page program in the side panel now reaches that card.

## CLI and daemon

- **Conversations whose id ends in a `c…` group work again.** Some conversation ids look like a web link's short code in their last group. The CLI took them for one and looked them up by reading every conversation in the Space, which failed with `503` once a Space held many conversations. A full conversation id is now always used directly. Reading and sending in those conversations works.
- **Agents found by full path start.** An Agent that the machine reported as installed at a full path outside the Run's `PATH` (for example the Windows Store Codex, or `claude.cmd` installed by npm) no longer fails with "not installed where xMatrix starts Agents".
- **An Agent that refuses this client says so.** When an Agent rejects the client itself (for example "This client is no longer supported"), the summon card shows the Agent's own words instead of asking you to sign it in again.

## Compatibility and updating

- Refresh the web app to pick up `4.14.2`. The live Hub already supports this release.
- Update the CLI with `xmatrix update`. The daemon restarts with the new version.

## Known limitations

- `xmatrix channels` without `--find` can still fail with `503` in a Space with many conversations. Use `xmatrix channels --find <words>` to find one.
- Desktop (`4.9.1`), Android (`4.6.2`), and iOS (`4.11.0`) are unchanged in this release.
