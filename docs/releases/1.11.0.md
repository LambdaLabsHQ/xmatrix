# xMatrix 1.11.0

Changes since 1.10.1. This Web update makes shared work easier to follow, adds
more Linear workflows, and gives the owner of an Agent a protected view of
its private connected-app results.

## Private results for the Agent's owner

- New private connected-app calls return the original to the calling Agent
  and display it automatically to that Agent's Human owner in the Web.
  Other Channel members, including administrators and other Agents, continue
  seeing the shared status without the private result.
- The owner's view requires current Channel access and lasts for 30 days.
  It displays private content as plain text, without shared-passage actions.
  Older results whose originals were never retained cannot be recovered.
- Public calls remain public. Command names and invocation parameters are
  still shared for private calls; keep credentials out of those parameters.

## More ways to work with Linear

- Find and filter tasks, assign people, change state and priority, and maintain
  projects, labels, comments and due dates from a Channel.
- Work with subissues, blocking dependencies, documents, milestones, project
  updates and linked attachments. Lists support bounded pages and cursors;
  task reads also accept Linear issue UUIDs.
- Text search uses Linear's current API. Project deletion is an explicit
  approval-gated action. Permanent task deletion is not offered.
- Linear creates cycles from the team's cadence settings; manual cycle
  creation is unavailable. Supported cycle reads, edits and task assignment
  remain available when the connected team uses cycles.

## Conversations and Pages

- The `@` menu lets you describe an Agent's strengths and opens **When to
  pick it** with the editor focused. The selection spans the row while the
  edit control remains separately clickable.
- When the Hub confirms that a Human message reached no Agent, its author can
  select an Agent under that original message. This works in named and welcome
  conversations and for later messages. Reopening the app or connecting a
  computer does not submit it automatically.
- Leaving a newly created Page before its first live sync preserves the
  words typed after the initial creation snapshot while that sync completes.
- Drag a Page onto the upper or lower half of another row to place it before
  or after that Page. Dropping below an expanded Page places the next sibling
  after its visible children. Touch scrolling and long-press remain available.
- Page conversation margins show quiet navigation lines and unread counts.
  The position rail marks conversations at their document passages and lets
  you jump to them; the comment count opens All / Open / Resolved filters.
- Compact previews show Page titles and readable Channel labels instead of ID
  fragments. Page edit cards stay steady while their content loads, and
  activity summaries follow the wording of the message they summarize.

## Clearer failures and steadier service

- A failed Agent turn shows the original error, with separate guidance for
  exhausted account quota and temporary rate limits. Structured reset times
  use UTC. When that same Agent replies later, its old failure card settles.
- Message headers wait for presence information before calling an Instance
  offline. Material Agent findings and decisions have clearer reporting
  guidance; existing Runs retain their launch instructions.
- Shared-service reads recover once after a lost database response in billing,
  registration quotas, Channel details, Page search and revision details. Machine reports and
  lifecycle writes also gain bounded connection recovery. Rebuilt database
  indexes reduce unnecessary scans during daemon reports and reconnects.

## Compatibility and known limitations

- Reload the stable Web. This release promotes no CLI/daemon, Desktop,
  Android or iOS binary; their device and installer verification remains
  separate. The shared Hub already serves the service-side changes.
- Messages without positive delivery evidence do not gain a guessed Agent
  choice. For older untracked questions, mention the connected Agent with
  your question. Editing, recalling or deleting a source, stopping its Channel, or
  losing access prevents a delayed choice from launching stale work.
- A new Page's pending first-sync handoff lasts at most 15 seconds. Closing
  the browser or a connection that cannot recover within that bound can
  still interrupt unsynchronized edits.
- Database recovery does not diagnose or eliminate the underlying transport
  stalls; a second failure still surfaces. Native devices, Provider sign-in
  and full multi-Agent recovery retain their separate verification needs.
