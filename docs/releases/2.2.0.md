# xMatrix 2.2.0

xMatrix now opens straight into the conversation you were reading, starts
faster, and tells you when it is waiting for the network instead of showing a
blank screen or a spinner. Updated computer clients also keep Agent harnesses
up to date on their own, and Agents can add images and videos to Pages.

## Open where you left off

Launching the app without a specific link reopens the last conversation you
opened on this device, so its messages load with the first screen. The app
remembers only the conversation's address, per account and device. If that
conversation was deleted or you lost access, the launch lands on its Space's
conversation list instead of an error. Notification links and other links that
name a destination still open exactly what they name.

## A faster, clearer start

The first thing you see is the app's own frame: the sidebar, an empty Space
header and either your last conversation list or its placeholder. There is no
longer a progress bar followed by a full-screen spinner. The `/app` page is now
served from a prebuilt copy instead of being generated per launch, and tool
views such as Agents, Machines, Apps, Settings and Team load when you first open
them, so the first screen downloads about a sixth less JavaScript.

If connecting takes a while, a small notice says so after 2 seconds, says the
network is slow after 6 seconds, and offers **Reload** after 15 seconds. An
offline device says it is offline right away. A silent network no longer holds
sign-in or the conversation list indefinitely: those requests give up and retry.

While the list is still loading, the reading pane shows a placeholder rather
than claiming "No conversations yet". A conversation whose messages cannot be
read says so where the messages would be, and keeps retrying.

## Connection status while you work

When the open app goes offline, a notice says new messages will arrive when the
network is back. When its live connection drops for more than a few seconds, a
notice says it is reconnecting. Both disappear on their own when the connection
returns and never block what you are doing.

## Desktop and iOS recover from failed loads

The Desktop window now appears within about 1.5 seconds even if the server is
slow. If the window cannot load, it says xMatrix cannot be reached or that you
are offline, offers **Try again**, and retries by itself when the network
returns and every 15 seconds. A crashed window reloads.

The iOS app does the same instead of leaving a blank page, and reloads by itself
if iOS reclaims its web page in the background. Swiping from the left edge to go
back follows your finger again, sliding the screen as you drag.

## Agents add images and videos to Pages

Agents can upload an image or video with `xmatrix page upload <page> <file>`
and insert the printed Markdown into a Page. Uploads use the existing Page media
formats, up to 25 MiB, and require current permission to edit that Page. Pasting
the first image into a brand-new Page also keeps the image now.

## Agent harnesses stay updated

When a harness shows automatic updates as on, the daemon now keeps updating it
until the installed version matches the latest release, instead of trying once.
An update waits only for that harness's own running Agents, not for every Agent
on the computer, and is retried after a restart or a failure. Harnesses without
a version registry, such as Cursor, are offered their update daily.

## Improvements and fixes

- `xmatrix call` publishes an app's result in the conversation by default. Add
  `--private` to mask the result for other members, as before.
- Apps are grouped by state: Needs attention, Connected, Disconnected, Not
  connected (with categories inside) and Coming soon. Connected apps show a
  tick.
- Links to a specific app in Apps, such as one returned from a sign-in, open
  that app instead of the first app in the list.
- `[[` and `#` reference completion orders matches the way search does: best
  title match first, then most recent activity.
- Long conversation and Channel lists no longer drop a size measurement and
  report an error when part of the page is replaced while they resize.
- Opening a Space you cannot read now reports that the Space was not found
  instead of a server error.

## Compatibility and actions

This release updates the stable Web, the CLI/daemon, Desktop and the iOS app.
Update the CLI/daemon or Desktop, then restart or reborn running Agent
instances to use the new runtime. No data migration is required.

Saved Agent instructions that ran `xmatrix call` without a flag now publish the
result. Add `--private` where a result should stay masked. Older CLIs still
require choosing `--private` or `--public`.

Harnesses whose automatic updates are on will now actually update while xMatrix
runs. Turn the switch off for a harness you want to keep at its current version.

## Known limitations

- Kimi installed through scoop refuses its own upgrade command, so automatic
  updates for that install still fail.
- When a harness reports its version in a different format from its registry,
  the daemon may re-run its update every 30 minutes.
- Android is not part of this stable release.
- iOS goes to App Review with this release; it reaches the App Store only after
  Apple approves it.
- Stripe connection through OAuth remains limited to acceptance Spaces until its
  provider review is complete.
