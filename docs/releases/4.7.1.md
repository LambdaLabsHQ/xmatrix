# xMatrix 4.7.1

This update is the CLI/daemon (`4.7.1`, up from `4.7.0`). The website stays on
`4.7.0`, Android on `4.6.2`, Desktop on `4.0.0`, and iOS on `4.0.4`. Hub changes
in this batch are already live.

## CLI and daemon

- **Daemons recover from journal checksum drift.** The continuity journals
  (boot, activation, and command-effect) verified their `checksumSha256` by
  deserializing the JSON payload and re-serializing it, so a one-unit-in-the-last
  -place float round trip could change the bytes. An Antigravity quota reading
  such as `(1.0 - 0.9004436) * 100.0 = 9.955639999999999` was enough to raise
  `activation journal checksum mismatch`, after which the daemon rejected every
  command and the machine could no longer start Agents. Journals now hash and
  verify the exact stored bytes, and a journal written by the previous release
  recovers automatically on upgrade. The command-effect journal also keeps a
  `.previous` copy and moves an unrecoverably corrupt file aside
  (`*.corrupt-*`, bounded) instead of refusing to start.
- **Antigravity stays busy while its subagents run.** Antigravity's ACP server
  marks `invoke_subagent` completed as soon as a subagent starts and emits no
  events while it runs, so the Instance dropped to `idle` and could sleep while
  background work was still running. Runs now count the session's active
  subagents, keep the Instance `busy` until each reports back or is killed, and
  keep listening between turns so an unsolicited background wakeup resumes the
  Run instead of waiting for a new message.

## Compatibility

- Run `xmatrix update` to upgrade the CLI and daemon from `4.7.0` to `4.7.1` on
  each machine. A daemon already refusing commands because of the checksum
  mismatch recovers its journals on startup after the update.
- No protocol or Hub change; the running Hub already serves this batch.

## Known limitations

- The website, Android, Desktop, and iOS keep their current versions (`4.7.0`,
  `4.6.2`, `4.0.0`, and `4.0.4`); the usage-meter rounding fix from this batch
  reaches the website with the next stable.
