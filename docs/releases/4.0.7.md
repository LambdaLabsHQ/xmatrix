# xMatrix 4.0.7

A summon can name a model again, and a stop or reborn that did nothing
says so. This update is the CLI and daemon. The website, the Desktop
app (4.0.0), Android and iOS are unchanged.

## Choosing a model in a summon

4.0.6 let a summon pick a model from the runtime's own catalog, but the
daemon never told the Hub it could, so the `@` menu offered no `model:`
rows and `@claude model:sonnet` was still refused. The daemon now
reports it. Once a Machine's daemon runs 4.0.7, the `@` menu lists each
runtime's models after its name, and a written `model:` matches the id
or a name the runtime gives it, such as Claude's `opus` or `Sonnet 5.5`.

## Stop, reborn and handoff

`@<agent>:<n>:stop`, `:reborn` and `:handoff:` that address no Instance,
such as a mistyped name or a full Instance id in place of the Channel's
number, used to leave their refusal only on the message. `xmatrix send`
now exits with an error that says the message was sent, quotes each
refusal and shows the form to resend, as in `@deepseek:3:reborn`.

## Already live

Connect with X reaches X's consent screen again; every connect had
ended on "You weren't able to give access to the App". This was a Hub
fix and needs no update.

## Updating

Install the CLI update; the daemon restarts on it. Model rows appear for
a Machine once its daemon is on 4.0.7. Accounts and saved content need
no migration.
