# xMatrix 3.0.0

Schedules are now tasks on their Page: read and change the instruction in the
same place as the work it keeps current. Large files can travel through a
conversation or a Page in parts, and computers learn about CLI updates as soon
as a release is available.

## A schedule is a line of its Page

Write a task with `🔁` for a recurring schedule or `⏳` for a dated reminder:

```markdown
- [ ] @auto review new issues and update this section 🔁 every day
- [-] @auto check the release notes 🔁 every week
```

Change the words to change the work. `[-]` pauses a task, `[ ]` resumes it and
deleting its line deletes the schedule. A delivered one-time reminder becomes
`[x]` with its completion date. Recurring tasks can also respond to supported
repository and app events. A line that cannot run as written explains why on
its Page and in `xmatrix page edit`.

Schedules lists the tasks under their Pages; **Edit on its page** takes you to
the instruction. A new run gets a fresh conversation. Use `@auto` or a harness
name in the task; a numbered Agent instance does not exist in that new
conversation. Without an Agent mention the task only posts its text.

An instruction runs with its author's access. Changing what it does transfers
it to the editor; pausing and resuming keep the author. The service checks the
current Page line before dispatching it.

## Large attachments and Page media

- Uploads larger than one request are sent in parts. A failed part can resume,
  and the complete file is made available only after its digest is verified.
- The CLI downloads attachments as a stream to disk, rather than holding the
  whole file in memory. It also uploads from disk and preserves audio and video
  media types.
- Conversations, Pages and Agent downloads agree on file types. More video
  formats display inline, and downloaded voice notes keep their audio suffix.
- Space storage usage is recorded. This release does not introduce a storage
  price. Files still have a technical ceiling of about 625 GiB; available
  storage and network conditions also apply.

## Computers check for updates sooner

The service tells online daemons when a newer CLI is published on their own
channel. A view that finds a computer behind can request a check immediately;
its progress says whether it is checking, installing, current or failed.
Older daemons retain their previous update behavior until they update.

OpenCode using an OpenAI model can now show the connected ChatGPT quota.
Cloudflare connections no longer request a nonexistent OAuth permission.
Codex stays available when its plan window is used up but purchased ChatGPT
credits still allow requests, instead of incorrectly showing LIMIT.

## Help an Agent sign in

An Agent can ask its owner to sign a harness in with
`xmatrix request sign-in <harness>`. The conversation shows a card that opens
that computer's sign-in flow; requesting the card does not grant credentials
or sign anyone in automatically.

Antigravity uses its managed `agy` CLI and ACP server, with install, update
and remote sign-in support. It requires version 1.4.11 or newer and the owner's
Google sign-in. Signed-in provider sessions still need their own live
acceptance; seeing an install or sign-in card does not establish that a turn
has completed. Windows also finds native Cursor and Antigravity launchers
when the daemon started before their installation updated PATH.

For Agents using ACP, local attachment copies remain available to the prompt,
unfinished or refused turns report their reason, and a restarted session
restores its model and effort when the provider still offers them.

## The public site also answers at xmatrix.page

The home, docs, downloads, legal pages and release notes are also available at
xmatrix.page, which becomes their canonical address on both hosts. Existing
xmatrix.sh links continue to work. The app and sign-in stay at xmatrix.sh;
opening them at xmatrix.page redirects there. OAuth callbacks, sessions and the
Hub keep their existing addresses.

## Easier summon conditions

After an Agent mention, the condition menu lists all condition kinds first.
It also offers the default model's available effort levels, so choosing an
explicit model is no longer required just to choose its effort.

## Security and reliability

Page task parsing and completion/status changes no longer stall on very long
whitespace sequences. Malformed lines cannot hold up later valid schedules.
The correction preserves task text, completion fields and schedule meaning.

## Compatibility and actions

This is a major release because the old Automation record-authoring interfaces
are removed. Existing stored references were migrated to Page task lines by the
service; the Page text now owns each schedule. The old
`[name](xmatrix:automation/...)` reference and create/edit/attach routes no
longer define or author a schedule. Edit the Page instead.

Update the CLI/daemon or Desktop to this release, then restart or reborn running
Agents to use the new commands and launch guidance. The CLI keeps
`page automation list`, `run`, `pause`, `resume` and `delete`; pause, resume and
delete change the Page line, without the old `--version` flag. Replace old `page automation create`, `edit`
and `attach` scripts with `page edit`. API integrations using the removed
record-authoring routes must also move to Page edits.

This release updates Web, CLI/daemon and Desktop. iOS 2.2.0 remains in App
Review and is not replaced; Android is not included.
