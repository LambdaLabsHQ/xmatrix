# xMatrix 3.2.0

Quote a passage without leaving its conversation, read new Gmail messages in
one card, and keep Agents connected and on the computer chosen for their work.
This release also includes Desktop sign-in and daemon detection fixes.

## Quote and discuss a message

Select words in a message to choose **Quote** or **Discuss in new channel**.
Quote holds the passage above the current composer; the next message includes
it with a link to its source. Discuss opens a separate conversation about that
passage and keeps the source conversation's linked Pages.

Quotes appear as one yellow paper slip. A quote from the same conversation
opens the original message and highlights its exact words. A quote from
elsewhere keeps its author and source inside the slip. Existing Markdown
quotes and the text Agents read keep their meaning.

## Gmail in one card

A new-mail notification now carries its automatic read in the same card.
The mailbox owner sees the message; other members and Agents see the
notification, without the private email body. Notifications still wake Agents
and Automations. A failed automatic read says so. The former 30-per-hour
automatic-read cap is removed; reads remain metered. Earlier notifications and
read receipts stay in history.

Gmail can send from a verified **Send mail as** alias on a connected mailbox.
The approval identifies both the alias and the mailbox used to send, and the
alias is checked again before sending. Replies to an alias can use that alias.
No new Gmail permission or reconnect is required.

Reads also recover the actual HTML message when the plain-text alternative is
only a prompt to view HTML or an empty template value. Large text bodies stored
by Gmail as references are fetched within bounded limits; real attachments are
not read. Excess or oversized body parts still show an incomplete notice.

## Agents reconnect and hand off more reliably

An Agent whose Run credential expires while its computer sleeps now requests
a scoped renewal when reconnect is refused, rather than repeatedly trying the
old credential until the periodic refresh. It keeps its Instance identity.

Handoff honors explicit computer and launch conditions and waits for the
source Instance's stop to be confirmed. An unavailable computer produces a
visible refusal. Work addressed to one exact Instance stays with that Instance;
peers receive context. New launch guidance identifies the current Instance and
Run and distinguishes completed temporary helpers from unfinished waits.

Agent message headers retain the repository admitted for that Run. Agents that
vanish before becoming ready report the failure instead of silently ending;
an intentional stop is not reported as a failed start. Claude processes started
by xMatrix identify xMatrix as their client. This does not promise any change
to a provider's quota or billing policy.

## Desktop and interface fixes

- On Mac, service sign-in opens in an independent window and returns focus to
  xMatrix, addressing the black main window after sign-in from a full-screen app.
- On Windows, Desktop checks the daemon's exclusive lock and gives process
  discovery more time, addressing false reports that a running daemon is stopped.
- App pages put sign-ins, Reconnect and Disconnect together at the top.
  Floating menus highlight to their edges, and long Page menus remain scrollable.
- Channel list reads no longer trigger repeated refreshes of every cached list
  merely because unrelated Space activity advanced its revision. Agent rest,
  wake and stop updates carry their current presence directly to open clients.
- Phone conversation navigation schedules its forward animation after the
  busy frame and creates its landing when it can play. Back and edge-swipe
  navigation keep their existing behavior.

## Updating and known limits

This release updates Web, CLI/daemon and Desktop. Refresh the website or reopen
the app for Web changes. Update the CLI/daemon or Desktop and normally reborn
existing Agent Instances to load the reconnect fix and new launch guidance.
Accounts, stored content and command permissions need no migration. iOS and
Android native packages are unchanged; installed stable shells receive the
updated stable Web. Existing settings-card limits described in 3.1.0 remain.

Desktop has automated suites and release checks; acceptance of the full-screen
sign-in and daemon fixes on the originally affected Mac and Windows computers
remains open. The latest phone forward-animation change also awaits confirmation
on an iOS device. These checks are not claimed as completed by this release.

Two known limitations remain: out-of-order presence snapshots
can temporarily omit an Agent avatar until a later update or reconnect, without
stopping its Run; and paginated App Store Connect purchase/review collections
may omit later-page items or incorrectly reject a named item. Do not treat a
large collection's current listing or default submission as a complete set.
Database lock diagnostics are improved, but underlying lock contention is not
claimed as resolved.
