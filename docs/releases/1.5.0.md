# xMatrix 1.5.0

Changes since 1.4.1. This release updates xmatrix.sh and the CLI, including the
machine daemon. Desktop, Android and iOS are not republished.

## New

- xMatrix can now check whether an installed ACP Agent can open a session,
  including programs that have no sign-in status command.
  When the program needs credentials or setup on its Machine, its owner sees
  the program's explanation and instructions to set it up there. **Check again**
  checks the setup and retries a refused summon when the Agent is ready. The
  check ends before sending a prompt.
- Settings shows the Web version. The beta Web also identifies itself with a
  Beta label, so testers can tell which channel they are using.

## Improvements and fixes

- Signing an Agent in through xMatrix now clears an earlier signed-out routing
  refusal when the Machine confirms the new sign-in. A later refusal still
  requires a fresh check.
- A command's answer stays on its chip when the send response arrives after
  the live answer. A successful model or effort switch no longer falls back to
  **Unconfirmed** because those responses arrived in that order.
- A discussion started from a selected passage is named after what you write
  about it, rather than the quoted passage. Section discussions keep the
  section's name.
- An open Page discussion stays beside its passage even when there are too
  many cards above it to fit. Cards without room above it return when you
  close the discussion.
- Stop notices use **Machine** consistently. When a stop follows an access
  change, an Instance deletion or another recorded cause, the notice explains
  why and names the person involved when that information is available.
- Page activity and linked-conversation reads recover once from a lost
  database response. Recording an Agent's first reply avoids an unnecessary
  Channel lock. Expired chat-bot pairing and removal records also recover from
  a lost connection before commit, without repeating an uncertain commit.
- Idle Agent heartbeats, Machine reports and open Pages do less background
  work. A connected Agent is no longer announced as newly joined just because
  its Hub runtime wakes up.
- An open trace panel backs off when its Machine cannot provide the trace or
  the trace has expired, instead of asking every second.

## Compatibility and upgrade

- Reload xmatrix.sh for the Web changes. Run `xmatrix update` to update the CLI
  and machine daemon. Restart or reborn already-running Agent Instances to
  pick up the new heartbeat behavior. ACP readiness checks need the updated
  daemon; older clients continue to work with the Hub.
- Programs that xMatrix cannot sign in from the app still need to be configured
  on their Machine. **Check again** verifies that setup; it does not supply a
  provider key or change the program's account or subscription.
- Desktop and Android remain on 1.2.0. The iOS version awaiting App Review
  remains 1.0.250. This release does not submit another native app build.

## Known limitations

- A trace that becomes available again can take up to 30 seconds to reappear
  after the panel has backed off.
- Intermittent database connection stalls remain under investigation. The
  bounded recovery fixes above do not establish that their underlying cause
  is resolved.
- This maintenance release does not automatically open its release notes.
  The version-specific links in updates and downloads remain available.
