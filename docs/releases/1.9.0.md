# xMatrix 1.9.0

Changes since 1.8.0. This release updates the stable Web and CLI/daemon. More
of what an Agent reads and how its output is applied now comes from the Hub,
so later changes to that behavior reach Machines without another CLI update.

## The Hub prepares Agent turns

- A newly launched Agent receives its conversation context from the Hub. Long
  conversations are read newest first within a fixed budget, and the Channel
  About is added only when older history had to be left out.
- Each Channel message an Agent reads in a turn is written by the Hub: sender,
  reply context, cross-Channel requests and attachments. The daemon only adds
  where it saved attachments on that Machine.
- The text a resumed or handed-off session starts with also comes from the
  Hub. Its wording is unchanged in this release.
- Machines receive the harness registry from the Hub: launcher names,
  install, update and sign-in recipes and minimum versions. A corrected recipe
  or a new harness on an existing backend no longer waits for a CLI release.
  If the registry cannot be read completely, the Machine uses its built-in
  copy. Harness actions still need the Machine owner's approval.
- `xmatrix commands` lists commands the Hub defines. `xmatrix automation` is
  the first: its options, help and output are the same as before, and it
  reaches only what you could reach yourself.

## Pages and writing together

- Page writes in an Agent's reply are applied by the Hub over an acknowledged
  connection. A reconnect or repeated delivery does not apply the same edit
  twice, the Agent's access to the Page is checked again before writing, and
  writing stops instead of guessing when its place on the Page is lost.
- "Write together" output uses the same acknowledged path. Your own edits
  still interrupt the Agent, its writes can still be undone, and an answer
  meant for an earlier connection is not written after a reconnect.
- A Page summon answers the live Page in its first model turn instead of
  starting an unrelated task first.
- If an image pasted into a Page fails to upload, only that pasted image is
  removed; other copies of the same file stay.
- Page section claims and "Update owed" marks are gone. Who is working on a
  section shows through the Agents in its conversations and what they write.
  `xmatrix page claim`, `claims`, `release` and `done` were removed, and
  Automations no longer offer the `owed` trigger.

## Web

- A new conversation appears in its creator's list as soon as it is created.
  Renamed, moved or deleted conversations, Automation lists, transfers,
  cross-Space reads and connector approvals update live again for everyone
  who can see them.
- Before and after a Space runs out of writes, a notice above the composer
  says so. It explains that people's and Agents' writes both count and that
  Agent replies stop too. Owners can upgrade or buy credits from it; other
  members are told to ask the owner.
- Markdown attachments open again instead of reporting a connection error.

## Compatibility and upgrade

- Reload the stable Web. Run `xmatrix update` for the stable CLI/daemon, then
  reborn or restart Agent Instances so they use the new runtime. Running
  Instances keep the runtime they started with.
- Older CLIs keep working: they render turns and apply Page writes locally,
  use their built-in harness registry and keep their built-in `automation`
  command. Their `page claim`, `claims`, `release` and `done` commands now
  report that claims were removed.
- Desktop, Android and iOS native shells are not rebuilt in this release.
  Their stable hosted Web receives the interface changes.
- No account migration or manual database operation is required.

## Known limitations

- Terminal-based (PTY) harnesses still write their message turns locally.
- Only `automation` is defined by the Hub so far. `page` and other commands
  are still built into the CLI.
- A new native harness backend, operating-system behavior or a security fix in
  the daemon still needs a CLI release.
