# xMatrix 1.3.0

Changes since 1.2.0. This stable release updates the CLI and machine daemon.
The Hub and Web improvements below have already reached production through beta
releases. Desktop, Android and iOS are not republished with this release.

## New

- Handing work to another Agent now carries the predecessor's conversation
  across supported harnesses and models, including requests, replies, tool calls
  and tool results. The successor starts its own session and receives readable
  context from Claude Code, Codex or Grok instead of relying only on Channel
  history.
- While writing a Page, type `[[`, `#` or `@` to complete links and mentions.
  Mentioning an Agent on a Page keeps the mention in the text and calls the
  Agent without requiring a separate brief.
- Select a passage on a Page to comment on it. Mention an Agent to direct the
  comment. An unnamed comment starts a new Agent matched to one working nearby,
  or uses `@auto` when none is present. Co-writing ends two minutes after the last
  person leaves the Page;
  reconnecting within that window keeps the session.
- A Page's change list shows edits made since you opened it, including other
  people's and Agents' edits. Undo can restore that opening state, with a notice
  explaining the change.

## Improvements and fixes

- The CLI's certificate verifier now rejects distrusted intermediate certificate
  authorities correctly. Its trusted root bundles are also updated.
- Handoffs from a first-message Agent, Page co-writing session or registered
  directory no longer fail with a spurious `forbidden` error when there is no
  repository checkout to export.
- New handoff conversation bundles and legacy session snapshots are private to
  their OS user. Each export gets an independent directory, resists precreated
  symlinks and cannot overwrite a previous export's files.
- The machine daemon can finish cleaning up an evicted repository checkout
  when Git has already unregistered it but directory removal was interrupted.
- Deleting a Channel asks you to confirm stopping its Agents before deletion.
- Page discussions open at their passage. Opening a conversation controls when
  the Page scrolls, and the Page edge shows who is working outside the visible
  area. Attachment cards and discussion controls are easier to read.
- Email-code sign-in recovery stays bound to the account that requested it.
  Mobile navigation and onboarding no longer lose their place during transitions.
- Agents' Page claims end when their Instance ends. Private Automation edits keep
  their author attribution. Connector commands use the same interpretation for
  execution and highlighting.
- The Hub recovers more reliably from lost database responses when reading
  Automations and Channels, routing Gmail, and deleting accounts or Channels.
  Sentry event processing and Gmail cleanup can also recover from a lost
  connection before commit without repeating provider calls or delivery.
  Background cleanup once again removes expired replay records within its work
  budget.

## Compatibility and upgrade

- Run `xmatrix update` to install the stable CLI. Machines need the updated
  daemon for conversation export during a handoff; older daemons can still hand
  off work but cannot supply the new conversation context. Already-running Agent
  processes retain their launch behavior until restarted or reborn.
- Handoff context is prior conversation, not instructions or permissions. The
  successor must verify the state it describes and starts a new provider session;
  it does not resume another harness's session.

## Known limitations

- Handoff context is bounded: it keeps the first request and recent entries,
  clips long entries, and omits reasoning, signatures and images. If the source
  transcript is missing or cannot be read, the handoff can continue without it.
- The update does not migrate or remove scratch copies exported by older CLI
  versions. Only newly exported handoff material uses the private bundle format.
- Conversation export still reads the source transcript in full, so very large
  histories can consume extra memory and delay extraction. Codex transcripts
  stored only under a custom `CODEX_HOME` may not be found.
- This release does not replace the iOS version currently awaiting App Review.
