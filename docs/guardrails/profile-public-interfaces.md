## Public Interfaces And Domain Contracts

- A handoff must change the stable Agent registration, whether on the same or another machine. A usage limit only holds the quota pool and posts an ordinary `handoff:@auto`. Same-machine directory handoff rejects the original harness; the repository-backed move to another machine excludes the predecessor's authoritative registration binding independently of quota refresh, so the same harness elsewhere is eligible. See `docs/same-machine-instance-handoff.md` §2.1–2.2.

- Direct runtime addresses (for example `@codex` and `@claude`) accept the same
  launch conditions as `@auto`, with an implicit runtime constraint. Completion
  emits direct addresses; historical `harness:` tags remain readable. Explicit
  registration selections keep their authorized tuple, and Markdown examples
  do not execute. See `docs/architecture/auto-launch-completion.md`.
- Composite registration preflight records a bounded cause when explicit
  launch conditions leave no authorized environment. Jev failures identify
  the environment or parameter phase and a safe provider or answer code;
  authorized invocation diagnostics present the same source-bound rejection.
- Repository registration admission verifies its exact reference against the
  execution-authorized Run; local directory admission checks the Workspace row.
  Registration settings edits preserve other configuration/resource fields and
  use configuration versions separately from policy revisions.


- PostgreSQL history presents attachment MIME kinds and exact message coordinates for Web and CLI consumers. Thread root copies persist their new attachment edge version; older copies missing that field recover it through a bounded, authorized history-page lookup of the exact attachment relation and content hash, without rewriting history or assuming an initial version.

- The Rust CLI has a versioned installation-local connection-profile registry with immutable opaque IDs, strict Hub origins, CAS revisions, exact-name selection, tombstones, and derived isolated state roots. One installation-level DaemonHost owns the OS service/control/update boundary while its ProfileManager supervises independently cancellable profile runtimes. Profile-scoped session, Machine, broker, Run, request/effect lineage, replica, cache, and Agent preset paths use the profile admitted at process entry; installation service/update state stays global. Local or Hub-requested runtime stop is scoped to one Profile, and update authority moves only among enabled, locally running actors. Default changes require an exact capability-authenticated revision acknowledgement that is independent from runtime health, and Desktop distinguishes monotonic follow-default selection from an explicit immutable profile. The host ready receipt records its generation, loaded revision, default ID, and per-profile initialization state.

- Agent quota is one owner-scoped directory record per declared pool (by default owner + machine + harness). Instance provider observations and daemon probes write that record using the original observation time; catalogs, live cards, `xmatrix list`, routing and the Agents management page project it. Instance token/context accounting stays local and survives sleep. The optional server `quotaState` explicitly clears expired/missing meters. Cross-Channel quota delivery derives recipients from current Channel membership, and reconnect reads repair missed notifications.
- Public channel and agent APIs include channel creation/update/delete, `parentChannelId`, ACL-derived visible Human member identities, derived channel presence, stable agent identities, live instances, instance workspace/machine context, trace payloads, usage/quota windows, attachments, and message history. Visible Human membership comes from Space membership for open Channels and owner/admin plus explicit Human grants for closed Channels; Human presence supplies status without becoming membership authority. A stable Agent identity has no aggregate runtime status: `online`, `busy`, `idle`, and `offline` belong only to concrete live instances. Run-scoped Agent list/history reads are limited to the birth Space and must apply current Owner-or-Agent Channel access before returning the same complete list serialization used by the Human view, except where the Run's owner has approved a read-only [cross-Space read grant](../cross-space-read-grants.md) for that exact live Run: outside the birth Space such a grant alone admits history, Channel memory, decision-evidence and catalog reads, made as the owner under the owner's current access, and never applies inside the birth Space; mutation, realtime delivery, and instance control remain active-Channel scoped. Agent attachment bodies are a narrower active-Channel read-through: the current Run token is bound to its birth Channel before the owning scoped authority rechecks the Human ACL and exact message relation, and no object locator or upload authority is exposed.
- Public connector APIs include Space-scoped connection lifecycle data and optional channel-scoped routing/subscription summaries. A disconnected Space connection retains its bounded installation reference and routing configuration for verified reconnection but authorizes no channel actions until reconnected. Channel summaries report current-channel binding and source subscriptions, require channel access, and expose only bounded provider source labels and feature names, never credentials or other channels' subscriptions. Connector actions follow the Space connection; there is no separate channel action allowlist.
- Legacy mixed-record migration persists a versioned aggregate completion report alongside its completion marker. Exact migrated and quarantined counts plus bounded reason groups are recorded when known; upgraded pre-report markers state that historical counts are unknown instead of inferring them from current Profile data.
- Channel archival recursively covers descendants and terminates every live agent instance active in the archived tree through the audited daemon-backed kill path; unrelated channel instances remain active.
- Mention semantics distinguish Human and exact Instance addresses, tagged Agent summons, reborn, stop/kill and handoff (same machine, or another through the repository). Human- and Agent-authored messages use the same authorization boundaries. An Agent can stop, reborn or hand off Instances in a Channel it can act in, its own and other Agents' alike; completing the first turn never implicitly exits. No routing decision selects a lifetime. Retired launch suffixes and lifecycle options are rejected.
- Coordinated work is owned by the entity it belongs to (docs/architecture/entity-coordinators.md): each Channel's `RelayPostgresAgentLaunchChannel` coordinates that Channel's launches, reborns, registration stops, terminal reports, routing retries and Automations; the writer of such work tells the owning Channel before answering and fails if it cannot; its alarm is the next due item, never a period. No Durable Object addressed by a constant name may coordinate work.
- PostgreSQL reborn persists an exact predecessor/successor intent before physical stop; the Channel's coordinator resumes stop confirmation and idempotent spawn after request loss. Transport-only offline presence does not revoke an otherwise valid exact Run reply proof; terminal and explicit lifecycle fences remain authoritative. Peer outbound broadcasts do not wait behind recipient inbound handlers.
- Repo-key warm worktree pooling (S1 co-trust + L1 reborn retention until explicit abandon) is the standard machine-local execution path for interactive explicit remote-repo Runs and has no product enablement flag. Machine-local worktree storage is fail-closed below a free-space watermark: ended `run-*` trees and stale named linked worktrees are reclaimed by default, missing bindings are pruned, new trees/slots are refused when the volume is exhausted, and only surplus Available pool slots may be evicted under pressure. Its sole cache key and on-disk partition is canonical repo identity; Hub user identity is authorization/audit context, not pool identity or slot selection. S1 co-trust means retained **arbitrary ignored bytes** (not only setup) may be reused across sessions after abandon. Hub source-message idempotency and the exact Machine Daemon command lease select one daemon. Every successful Workstation connection advances a durable Hub epoch that fences prior daemon claims, reports, completions, retries, unregister, and local pre-spawn admission. The active daemon serializes same-repo base materialization and pool mutations with in-memory repo-keyed coordinators while different repositories remain parallel; the filesystem stores durable state but no repo scheduling lock. Eligible explicit repo spawns and pooled reborn use exact durable daemon bindings; pool authority stored with the prior Run is mandatory for pooled reborn, while authority-absent historical Runs alone stay on legacy `run-*`. A pooled spawn remains `Starting` until the daemon revalidates its connection epoch, exact command lease, and derived formal linked worktree, then consumes a one-shot token immediately before OS spawn; exact replay rotates an unconsumed token, and private provisional sidecar state preserves crash recovery without admitting two writers. Natural exit and ordinary stop retain the same cwd. A later new same-repo lease takes an idle Available or oldest idle Retained slot before creating another linked worktree; if that idle slot is no longer a formal linked worktree, or its `.git` pointer belongs to another local clone of the same remote, the daemon treats it as leftover and continues rather than failing the spawn. The pool parent is only the daemon-managed clone; a registered workspace checkout of the same remote must never become that parent. Exact reborn of a missing Retained tree fails closed. Public Instance DELETE first fences the exact current Instance version and Run, serializes against an in-flight exact spawn when needed, then performs stop → exact typed abandon → terminal commit; pending and committed delete fences reject reborn, so returned slots cannot be paired with stale recovery authority. An already-terminal historical non-pooled Run can commit that delete fence directly only from exact authenticated daemon terminal evidence, not domain status such as archive. Exact completed-return receipts recover registry-persist crashes without re-retaining an Available slot. All eligible repository Runs use the pool. Natural exit retains their workspace; explicit abandon and idle sleep reclamation use the established snapshot gates. UI-attached VS Code launches remain a separate executor.
- Mention completion exposes one grammar segment at a time. Selecting an agent or connector advances to its immediate children, selecting a concrete agent instance enables schema-declared commands such as `/model` and `/goal`, GitHub repository commands advance through owner/organization and repository stages, and reaching a free-form argument boundary closes enumeration.
- Instance identity has two explicit layers: `instanceId` is the globally unique live instance id for traces, controls, storage, audit, reconnect blocking, and cross-channel reasoning; `channelInstanceId` is only the per-channel ordinal for channel-visible addressing and display such as `@agent:1`.
- The active `xMatrix` delegate is addressed as `@xMatrix` rather than with an ordinary channel ordinal, but its lifecycle actions use the normal instance APIs and channel-scoped authorization. The backing Agent profile must not appear as a duplicate product identity or control row.
- PostgreSQL message appends derive management sender presentation from the exact live Run and current Space management configuration, checking the configuration again in the commit transaction. Management mentions display the xMatrix name and avatar while preserving underlying Agent, Run, and Instance ids for attribution. Caller-supplied sender fields cannot grant this presentation; existing stored snapshots are not rewritten.
- Agent trace/details should remain human-readable, but the Agent host is the canonical trace source. Hub may expose only a bounded session-lifetime cache or an exact authenticated on-demand host fetch; once the session/instance expires it clears the cache, and an unavailable host yields an explicit unavailable result rather than stale Hub history.
- Assistant memory is exposed as a Hub-authenticated per-user typed projection. It stores compact entries, checkpoints, and source refs so assistant instances can resume from a snapshot instead of replaying raw assistant-channel history.
- Recent Android, Desktop, and CLI stable downloads are served from verified immutable prefixes in the dedicated `xmatrix-release-assets` R2 bucket through Web routes; the mutable channel pointer advances only after complete readback. Large release objects use bounded streaming R2 S3 multipart uploads when the bucket-scoped credential pair is configured, while every upload retains independent size and SHA-256 readback. Cross-runner handoffs remain run-and-attempt scoped; a failed-job finalizer rerun may select the newest complete manifest independently per platform from earlier attempts of the same run, but never crosses a run or accepts an incomplete prefix. GitHub Releases retain historical component archives through an independent post-CD mirror and remain the fallback when no recent R2 channel object exists. Android uses `android-v<version>`, Desktop uses `desktop-v<version>`, and CLI uses `cli-v<version>`. Every macOS CLI asset is Developer ID signed with the stable `net.madebyrobot.xmatrix.cli` / `VWN9V9V56Z` requirement before upload so the daemon retains access to its encrypted-replica Keychain item across self-updates.
- GitHub connector customization is channel feature subscription, not a GitHub permission editor. The default path is the xMatrix GitHub App plus GitHub-native repository access and permission approval; customer-owned GitHub Apps may become an advanced deployment path while preserving installation and secret-reference boundaries.
- GitHub Actions mutations use two typed connector atoms: failed-job rerun and workflow dispatch. Both require one explicitly configured Actions write Channel and a freshly minted repository-scoped installation token that reports Actions write permission; workflow dispatch additionally requires the exact workflow file name or numeric id in the connection allowlist. Persisted connector scopes do not substitute for live installation authority, and no arbitrary GitHub REST path is exposed.

Host-command approval is retired: Agents run host commands as the owner's user
and read their Space's secrets when they need them with `xmatrix secret exec`
(`auto`, or `ask` a Space admin on a card). See
`docs/daemon-request-broker.md`.

New local repo pools use 8-hex repo directories and 6-hex slot directories,
with an exclusive full-key claim, bounded slot collision retries, and manifest
version 2. Existing 64-hex pool directories and version 1 manifests stay in place
for live/retained worktree compatibility. Authority fields remain unchanged. See
`docs/worktree-v2-design.md` for layout, collision handling, and downgrade limits.
