## Important Directories

- `packages/decision-model`: Jev evaluation client through Vercel AI Gateway, used by `pnpm jev:evaluate` and the authenticated Hub endpoint `/api/ai/jev/evaluate`. The Hub retains the provider key and limits callers by deployment configuration. See `docs/operations/jev-evaluation.md`.

- Space agent routing adds owner-declared environments, freshness-aware candidate selection, optional Jev semantic matching and PostgreSQL-fenced startup fallback across compatible harnesses and machines. See `docs/architecture/space-agent-routing.md` for the contract, rollout order, measured coverage and remaining canary requirements. This is an xMatrix capability of choosing among the owner's own agents.

- Auto invocation uses a unified keyboard completion list: selecting a repository, model or machine creates an `@auto` mention with editable condition tags. `@` is parsed within the committed Channel message; launch authority uses that publication and its Channel context without a second message body. Jev receives a bounded privacy-safe projection of the message and may retry one transient gateway failure without a server-picked fallback. The portable parameter block, Jev eligibility, persisted constraints, runtime effort validation and rollout contract are described in `docs/architecture/auto-launch-completion.md`. The reserved `@xMatrix` management assistant keeps its existing meaning.

- `apps/web`: Next.js 15 / React 19 dashboard deployed to Cloudflare through OpenNext.
- `packages/hub`: Cloudflare Worker and Durable Object relay, auth, channel, agent, and subscription backend.
- `packages/cli-rs`: Rust `xmatrix` CLI, daemon, agent launcher, provider-specific Codex, Claude Code, Grok Build, and ZCode runtime adapters, a generic ACP adapter for harnesses that speak the Agent Client Protocol over stdio (Kimi Code, Cursor, OpenCode, GitHub Copilot CLI, Gemini CLI, Qwen Code, goose, Junie, Mistral Vibe through `vibe-acp`, Kiro CLI, Hermes Agent, OpenClaw through its Gateway bridge, Qoder CLI, CodeBuddy Code, Oh My Pi, Auggie, Cline, Kilo, Factory Droid, Devin, Command Code, jcode, Prime Agent, TraeCode CLI, Google Antigravity through its standalone ACP server, Reasonix, DimCode, Autohand Code and Amp through their ACP adapters, and Pi through the ACP-registry `pi-acp` bridge), terminal and update flows. `packages/cli-rs/crates/harness` (`xmatrix-harness`) is the independently publishable harness library: it owns the usage wire types and provider account-quota probes and depends on no other xmatrix crate. `crates/process-tree` owns native process lifetimes and `crates/repo-pool` owns repository leases and run worktrees; runtime orchestrates them through crate interfaces, so each subsystem compiles and tests separately. The harness registry is `packages/protocol/src/agent-presets.json`; Rust and TypeScript derive launcher aliases, agent types, config directories, and install hints from it rather than enumerating harnesses in code.
- `packages/protocol`: Shared TypeScript protocol types consumed by Web, Hub, and CLI-generated bindings.
- Runtime execution symptoms are projected once at the common Agent Instance connection boundary, independently of harness identity. Optional ACP v1 Session Notices feed the same public summary path; advisory severity does not change task lifecycle. Raw diagnostics remain in the host trace. See `docs/design/agent-status.md` §6 for the shared mechanism and compatibility limits.
- `apps/android`: Native Android WebView shell. Loads the live web app first and keeps packaged assets as fallback.
- `apps/ios`: Native iOS WKWebView shell with a compatible `window.xmatrixDesktop` bridge.
- `apps/desktop`: Electron shell and updater for the live web app.
- `scripts`: Version, release, Android, iOS, and GitHub release automation.
- `.github/workflows`: CI, deploy/release, and self-hosted runner maintenance workflows for web, hub, CLI, Android, iOS, desktop, macOS SSH authorization, Xcode setup, and runner scaler setup/recovery. Private product validation and release builds default to self-hosted runners; public snapshot CI uses GitHub-hosted Ubuntu 24.04 and Windows 2025, with reusable JSON runner inputs and no ledger reuse on hosted jobs; every Linux release job (planning, validation, builds, deploys, finalizers, archival, Test/Production brokers) runs on the US machines via `xmatrix-us-release` and `xmatrix-release-test`. Private GitHub-hosted Ubuntu is also used for recovery and R2 storage maintenance. `scripts/ci.mjs` runs Oxlint in Node checks and complete-workspace Clippy (`-D warnings`) in the Linux Rust partition; see `docs/operations/ci-lint-and-public-runners.md`.
- `.github/scripts`: Hosted/self-hosted runner setup, release, cache, and recovery helper scripts used by GitHub Actions.
- macOS release jobs inherit host-managed routing, including the M1 runner's sing-box proxy with domestic mirror/local-DNS bypass and its existing Singapore overseas outbound. Release and manual disk cleanup share a checkout-bounded cleaner; machine-wide PNPM/Electron caches survive jobs, and shared PNPM pruning is offline host maintenance.
