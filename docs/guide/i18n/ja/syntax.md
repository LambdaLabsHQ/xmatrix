# メッセージ構文

xMatrix への指示はすべて通常のテキストメッセージです。隠れたフォームは一切なく、入力したテキストがそのまま保存され、サーバーも目に見えるテキストをそのまま解釈します。コンポーザーで `@`、`#`、`[[` を入力すれば補完候補が表示されるため、構文を暗記する必要はほとんどありません。このページではすべての記法を解説します。

## クイックリファレンス

| 入力例 | 動作 |
| --- | --- |
| `@claude fix the failing test` | 新しい Claude インスタンスを起動してタスクを依頼 |
| `@auto repo:acme/api fix the failing test` | xMatrix にエージェントを選ばせ、`acme/api` の worktree で起動 |
| `@codex pwd:"/Users/me/my app" …` | 登録済みディレクトリ内でそのまま（インプレースで）起動 |
| `@codex model:<id> effort:high …` | 特定のモデルと推論強度（effort）を指定して起動 |
| `@claude:2 also update the changelog` | この会話の Claude インスタンス 2 に続けて指示 |
| `@claude:2 /model <id>` | 稼働中のインスタンスのモデルを切り替え |
| `@claude:2:stop` | そのインスタンスを停止 |
| `@claude:2:reborn` | 記憶を保持したままそのインスタンスを再起動 |
| `@claude:2:handoff:@codex finish the migration` | チェックアウトを新しい Codex インスタンスへ引き継ぎ |
| `/stop all` | 会話内のすべてのインスタンスを停止 |
| `@Maya` · `@everyone` | 特定のメンバー、または会話内の全員に通知 |
| `@github:subscribe:acme/web pulls checks` | 連携アプリのアクションを実行 |
| `page:<id>` · `channel:<id>` | ページまたは会話を参照 |

## メンション

メンションは `@` の後ろに名前を続けた表記です。メッセージの先頭、または空白・開き括弧の直後に `@` がある場合に認識されます。全角の `＠` も `@` と同様に機能します。

名前は大文字・小文字を区別せず、最長一致で判定されるため、`@codex-mba` が `@codex` として誤認識されることはありません。

エージェントを起動・操作するメンションは独立した 1 語として扱い、直後にスペース・改行・閉じ句読点を入れてください。人への通知のみのメンションは、日本語や中国語のテキストにそのまま続けて書けます（例：`@Mayaの案`、`@Maya的方案`）。

### メンションとして扱われない箇所

以下の箇所に含まれるメンションは単なるプレーンテキストとなり、通知も起動も行われません。

- インラインコードおよびコードブロック
- 引用ブロック（ブロッククォート）
- リンクおよび画像
- 取り消し線テキスト

構文を説明したいだけで実際に起動させたくない場合は、バッククォートで囲んでください。

### メンバーへのメンション

`@` を入力してメンバーを選びます。表示名（`@Maya Chen`）またはハンドル名でメンションできます。メンションされた人には通知が届き、既読になると通知が消えます。

`@everyone`、`@channel`、`@all`、`@here` は会話に参加している全メンバーに通知します。

同名のメンバーが複数いる場合や、メンバー名とエージェント名が衝突する場合は、ハンドル名で指定するまでメッセージ送信が拒否されます。

## エージェントを起動する

ハーネス名をメンションすると、その会話で**新しい**エージェントインスタンスが起動します。

```text
@claude rework the hero so it shows the product
@codex check the mobile breakpoints
@auto find out why billing webhooks retry twice
```

- `@<harness>` は特定のハーネスを指定します（`@claude`、`@codex`、`@cursor`、`@gemini` など）。詳しくは[対応ハーネス](agents.md#supported-harnesses)を参照してください。
- `@auto` は xMatrix に選択を任せます。タスク内容を読み取り、最も適したハーネスを、余力のあるマシン上で起動します。

メンション以降のテキストがタスク内容になります。エージェントには前後の会話履歴も渡されるため、直前の議論で文脈が明らかなら `@claude take this one` のような短い指示だけで十分です。

### 起動条件

起動条件を使うと、エージェントの実行場所や設定を絞り込めます。メンションの直後にスペース区切りで `key:value` 形式の語を並べます。

```text
@auto repo:acme/api model:<id> effort:high find out why webhooks retry twice
```

この例では `@auto` がメンション、続く 3 語が起動条件、`find` 以降がタスク本文です。

| 条件 | 意味 |
| --- | --- |
| `repo:<owner/repo>` | 指定リポジトリの新しい管理 worktree 内で作業する |
| `pwd:"<absolute path>"` | 指定した登録済みディレクトリ内でそのまま作業する |
| `machine:<name>` | 所有者が付けた名前で特定のマシンを指定して実行する（`xmatrix agent list` で名前を確認可能） |
| `harness:<name>` | `@auto` と併用し、選択候補を特定のハーネス 1 つに限定する |
| `model:<id>` | 指定したモデルを使用する |
| `effort:<level>` | 指定した推論強度（effort）を使用する |
| `fast:on` | ハーネスが対応している場合、高速モードを有効にする |
| `param.<id>:<value>` | ハーネスが公開しているその他のオプションを設定する |

ルールは次のとおりです。

- **条件に該当しない最初の語で条件指定は終了します。** その語以降はすべてタスク本文として扱われます。未知の `key:value` もエラーにならず通常のテキストになります。
- **順序は自由**で、各条件は最大 1 回まで指定できます。
- **条件はメンションと同じ行に書きます。** 改行すると条件指定は終了します。
- **空白を含む値はダブルクォートで囲みます。** 値の中にリテラルのダブルクォートを含める場合は 2 つ重ねます（例：`pwd:"/Users/me/my ""old"" app"`）。
- **満たせない条件があると起動は中止されます。** xMatrix が別のモデルやマシンへ勝手に差し替えることはありません。起動しなかった理由はメンション上に表示されます。

### エージェントの作業場所

`repo:` と `pwd:` は排他関係にあり、1 つのメンションにはどちらか一方のみ指定できます。

**`repo:`** はリポジトリを指定します。エージェントには専用の worktree が割り当てられるため、複数のエージェントが同じリポジトリで同時作業しても互いの変更を上書きしません。GitHub リポジトリは `owner/repo` 形式で書きます。HTTPS や SSH の完全なリモート URL も使用でき、GitHub URL の場合は自動的に `owner/repo` へ短縮されます。認証情報、クエリ文字列、フラグメントを含む参照は受け付けられません。

```text
@codex repo:acme/web …
@codex repo:https://gitlab.example.com/team/service …
```

**`pwd:`** は、`xmatrix workspace register` でマシン上に登録済みのディレクトリを指定します。エージェントはそのディレクトリ内で、現在のチェックアウト状態のまま作業します。絶対パスで指定する必要があり、同時にそのマシンも特定されます。

```text
@claude pwd:/srv/app …
@claude pwd:"C:\Users\me\my app" …
```

どちらも省略した場合、xMatrix はタスク内容と名前・説明の照合から Space 内のリポジトリやディレクトリを自動選択します。会話の流れから自明でない場合は、明示的にリポジトリを指定してください。

### モデル・推論強度・その他のオプション

`model:` と `effort:` には、ハーネスが報告する ID を指定します。コンポーザーでハーネスを選ぶと候補が表示され、[Agents 画面](agents.md)でも確認できます。

モデルと推論強度以外のオプションはハーネスごとに異なるため、固定キーワードではありません。各ハーネスが公開するオプションを `param.<id>:<value>` で指定します。

```text
@kimi param.<id>:<value> summarize the incident
@codex fast:on apply the rename
```

ハーネスが現在公開している ID と値はコンポーザーに一覧表示されます。`fast:on` は `param.fast:on` の短縮形です。スイッチ型オプションは `on`、`off`、`true`、`false` を受け付けます。

### 誰がエージェントを起動できるか

xMatrix のコンポーザーから送信したメッセージは、呼び出したエージェントを起動します。一方、エージェントが送信したメッセージから別エージェントを起動できるのは `xmatrix send --launch` を使った場合のみです。`--launch` がなければ、報告文中の `@codex` は単なるメンションとして扱われるため、エージェント同士が誤って連鎖起動することはありません。停止・reborn・handoff の挙動はいずれの場合も同じです。

起動しなかったメンションにはその旨が表示され、投稿者はそこから手動で起動できます。メッセージ本文の記述だけで強制起動することはできません。廃止された `launch:force` 条件は無視されるため、エージェントがレポート内にそれを書いて別のエージェントを起動することはできません。

### 新しい会話の最初のメッセージ

新しい会話の最初のメッセージに誰もメンションされていない場合、どのエージェントに担当させるか（または起動しないか）を数秒間選択できます。選択しなかった場合、xMatrix はメッセージを読み取り、作業依頼と判断した場合のみエージェントを起動します。

2 件目以降のメッセージで誰もメンションしない場合、新しいエージェントは起動されません。すでに会話に参加しているインスタンスが文脈として受け取り、返信すべきかを自ら判断します。

## インスタンスに話しかける

各インスタンスには会話内での番号が振られ、名前の横に表示されます（`claude:1`、`codex:2`）。話しかけるときは `@<name>:<number>` と書きます。

```text
@claude:1 the tests still fail on Windows, take another look
```

メッセージはそのインスタンスだけに届きます。スリープ中であれば自動的に復帰します。番号は会話ごとに独立しているため、別の会話の `claude:1` とは別インスタンスです。

インスタンスのメッセージに対する返信も、メンションなしでそのインスタンス宛てとして扱われます。

同じ会話内の他インスタンスはそのメッセージを文脈として閲覧できますが、他者宛てのメッセージに反応して作業を始めることはありません。

## 稼働中インスタンスへのコマンド

特定のインスタンス宛てに `/` で続けるメッセージは、タスクではなくそのインスタンスへの制御コマンドになります。

| コマンド | 効果 |
| --- | --- |
| `@claude:1 /model` | このインスタンスで利用可能なモデル一覧を表示 |
| `@claude:1 /model <id>` | モデルを切り替え |
| `@claude:1 /effort` | 利用可能な推論強度（effort）一覧を表示 |
| `@claude:1 /effort <level>` | 推論強度を切り替え（`/reasoning` も同じ） |
| `@claude:1 /config <id>` | 公開オプションの選択肢と現在値を表示 |
| `@claude:1 /config <id> <value>` | オプション値を変更 |
| `@claude:1 /fast on` · `off` · `status` | 高速モードの制御（引数なしの `/fast` でトグル） |
| `@claude:1 /goal <condition>` | 複数ターンにわたって達成を目指す完了条件を設定 |
| `@claude:1 /goal status` · `pause` · `resume` · `clear` | ゴールの状態確認・一時停止・再開・クリア |

設定変更は稼働中のセッションへ即座に適用されます。インスタンスは記憶とチェックアウトを保持したまま続行し、再起動は不要です。

`/model` と `/effort` はメッセージ全体がコマンドである必要があります。1 行に 1 つずつ書けば、1 通のメッセージに複数まとめられます。

```text
@claude:1 /model <id>
@codex:2 /effort high
```

他のテキストが混ざっている場合は通常の作業依頼として配信されるため、設定が中途半端に適用されることはありません。

ハーネス独自のスラッシュコマンドも利用できます。コンポーザーで `@<name>:<number> /` と入力すると、稼働中のインスタンスが対応するコマンド一覧が表示され、そのままハーネスへ渡されます。

## 停止・再起動・引き継ぎ（ハンドオフ）

会話で操作権限を持つメンバーなら誰でもインスタンスを制御できます。エージェント自身も可能です。

| 入力例 | 効果 |
| --- | --- |
| `@claude:1:stop` | このインスタンスを停止（`:kill` も同じ） |
| `@claude:1:stop wrong branch` | 理由を添えて停止（停止表示に理由が出ます） |
| `/stop all` | 会話内の全インスタンスを停止（`/kill all` も同じ） |
| `/stop claude:1` | 1 つのインスタンスを停止する別記法 |
| `@claude:1:reborn` | セッションとチェックアウトを保持したまま同じインスタンスを再起動 |
| `@claude:1:handoff:@codex` | 作業内容と会話文脈を新しい Codex インスタンスへ引き継ぐ |
| `@claude:1:handoff:@auto` | 引き継ぎ先の選定を xMatrix に任せる |

**Stop** はメッセージ全体がコマンドである必要があり、コマンド以降のテキストは停止理由として扱われます。停止されたインスタンスは新しいメッセージでは復帰しません。復帰できるのは `:reborn` のみです。

**Reborn** は同じインスタンスを、同じ番号・同じ記憶・同じディレクトリで再起動します。インスタンスが詰まったとき、復帰に失敗したとき、または停止状態から戻したいときに使います。メンションの後ろにテキストを添えると、再起動後のインスタンスへそのまま渡されます。

**Handoff** は、引き継ぎ元のインスタンスが確実に停止したことを確認してから、別のインスタンス（多くの場合は別ハーネス）を起動します。ルーティングには通常の起動と同じ認可・検証が適用されます。明示的な `machine:` 条件付きで起動されたインスタンスは、クォータ自動ハンドオフを含め同じマシンを維持します。暗黙配置だった場合は別マシンへの移動も可能です。指定マシンに適格な後継がいない場合、ハンドオフは理由付きで明示的に拒否されます。停止処理が保留中の間は後継を起動しないため、引き継ぎ元のデーモンが終了を確認してから再試行してください。

後継指定の直後には通常の起動条件構文が使えます。`@claude:1:handoff:@machine:Laptop` や `@claude:1:handoff:@model:<id> effort:high` のように条件から直接始めて、ハーネス選択をルーティングに任せることもできます（通常起動の `@machine:Laptop` と同様です）。明示的なマシン上書きは引き継いだ条件を置き換え、現在のアクセス権と稼働状況のチェックを受けます。モデル・推論強度・ハーネスパラメータも通常どおり検証され、これらが明示指定された場合、他に優先される登録がなければ引き継ぎ元自身の登録上で新規インスタンスを起動できます。リポジトリやディレクトリの条件は引き継ぎ元の作業場所と一致している必要があります（作業場所を変える場合は新規タスクとして起動してください）。条件以外の最初の語からタスク本文が始まります。

```text
@claude:1:handoff:@codex you have the branch; finish the migration and open the PR
@claude:1:handoff:@codex machine:Laptop effort:high continue in the original browser
@claude:1:handoff:@machine:Laptop model:<id> effort:high finish the migration
```

後継は常に新規インスタンスになるため、番号なしで名前を指定します。`@auto` と書けばハーネス選択もルーティングに任せられます。

リポジトリのチェックアウト（未コミットの変更を含む）はハンドオフ用ブランチ経由で引き継がれます。登録済みディレクトリはそのマシン上に留まります。引き継ぎ元からエクスポートされた会話は先行文脈として渡されますが、後継のアイデンティティやセッションそのものにはなりません。ブラウザセッションなどのローカル状態はチェックアウトと一緒に移動しません。

特定インスタンス宛ての指示は対象インスタンスのタスクとなり、他のインスタンスには文脈として共有されます。会話全体への通常メッセージは共有タスク、ブロードキャストは全員宛てとして扱われます。エージェントの信頼された実行時インスタンスおよび Run ID は、リカバリを通じて一貫して識別されます。一時的なヘルパーエージェントは、依頼完了後に最終報告を送って自身を停止すべきです。人や CI の結果を待っているインスタンスはまだ作業が残っているため、待機状態を維持します。

プロバイダーのクォータが枯渇すると、xMatrix は自動ハンドオフを試みます。引き継げる適格な環境がない場合は、**Retry when quota recovers**（クォータ回復時に再試行）または **Not now**（今はしない）を選べます。待機はページを閉じても継続し、いつでもキャンセル可能です。待機は 35 日で期限切れとなり、再試行前には実際のプロバイダークォータが確認されます。

## 連携アプリ

Space に連携したアプリも、エージェントと同様にアクション付きで呼び出せます。

```text
@<app>:<action>:<target> <text>
```

```text
@github:subscribe:acme/web pulls checks
@github:comment:acme/web:#42 Reproduced on main.
@sentry:resolve:<issue>
```

コマンドはメッセージの先頭に書く必要があり、1 通のメッセージには 1 つのコマンドのみ含められます。2 行目以降はテキスト本文として扱われます。利用可能なアプリとアクション一覧は[連携アプリ](connectors.md)を参照してください。

## 参照

| コンポーザーでの入力 | メッセージ内の保存形式 | 表示形式 |
| --- | --- | --- |
| `[[` を押してページを選択 | `page:<page-id>` | ページの現在タイトルを表示するチップ |
| `[[page#` を押してセクションを選択 | `page:<page-id>#<heading-slug>` | そのセクションを開くチップ |
| `#` を押して会話を選択 | `channel:<channel-id>` | 会話の現在名を表示するチップ |

参照の実体は ID なので、ページや会話の名前を変更しても過去のメッセージが壊れることはありません。参照自体は権限を付与しないため、閲覧権のないユーザーにはタイトルもリンクも表示されません。会話の中でページを参照すると、そのページが会話にリンクされます。

ページ本文中に書かれた `page:<page-id>` や `channel:<channel-id>` も同様にチップ表示され、キャレットを置いたときだけ元の ID が見えます。

`#` の直後に数字が続く場合は通常のテキストとして扱われるため、`#3484` のようなプルリクエスト番号はそのまま残ります。中国語 IME では `【【` でもページ一覧を開けます。

## 制限値

- メッセージ本文は最大 131,072 文字です。
- 1 通のメッセージに含められるコマンドは最大 8 個です。
- インスタンス名・マシン名・モデル ID・推論強度は最大 160 文字、パスやリポジトリ参照は最大 4,000 文字です。

## 起動しないときの確認ポイント

メンション自体に現在の状態（待機中・作業中・返信済み・失敗・停止）と理由が表示されます。よくある原因と対処法は次のとおりです。

| メンションに表示される内容 | 対処法 |
| --- | --- |
| Mentioned, not started（メンションのみ・未起動） | 起動指定なしで送信されています。メンション上の Start を押すか、`xmatrix send --launch` で再送してください |
| No registered environment offers the requested model, effort or harness | ハーネスが報告する ID を確認するか条件を外してください。`xmatrix agent list` で各マシンの対応ハーネスを確認できます |
| The requested machine does not run this Agent | `xmatrix agent list`（または Agents 画面）で、各マシンのハーネス・オンライン状態・クォータを確認してください |
| The requested directory is not authorized | 対象マシンで `xmatrix workspace register` を実行してディレクトリを登録してください |
| The repository reference is invalid | 認証情報を含めず `owner/repo` 形式で指定してください |
| Every matching environment has used up its provider quota | クォータのリセットを待つか、別のハーネスを指定してください |
| Only machines kept out of automatic assignment can run this | `machine:<name>` でマシンを明示指定してください |
| The `:new` and `:once` suffixes are retired | `@agent:new:owner/repo` ではなく `@auto repo:owner/repo` を使用してください |

ターミナルから `xmatrix diagnose <conversation>` を実行しても同じ診断結果を確認できます。
