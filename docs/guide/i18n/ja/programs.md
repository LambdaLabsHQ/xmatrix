# プログラム

プログラムは、複数のエージェントと人がどのように 1 つの仕事をやり遂げるかを記述します。誰に何を依頼するか、どの順序で、いつまでに、そして断られた場合や無応答だった場合にどう振る舞うかをページ上に一度書けば、あとは xMatrix が実行します。人間がエージェント間で伝言ゲームをしたり、返事の催促を覚えておいたりする必要はありません。

プログラムはオープンなコーディネーション言語 [Norn](https://norn-lang.org) で書きます。xMatrix はその実行ホストとして、すべてのリクエストの記録、配信、タイマー管理、および Space 権限の適用を担います。自分のチームで動かす前に、[Norn プレイグラウンド](https://norn-lang.org/norn/)の模擬チームで言語を試すこともできます。

## 最初のプログラム

ページを開き、`norn run` と名前を付けたコードブロックを追加して保存します。

````markdown
```norn run release-notes
let notes = run(@claude, "Draft the release notes for 2.4")->wait?
switch confirm(@alice, "Publish these notes?", ~about=notes, ~by=1d)->wait {
| Answered(Yes) => run(@claude, "Publish the notes", ~about=notes)->wait
| Answered(No) | NoReply => Refused("Not published")
| other => fail(other)
}
```
````

`@claude` は Space 内のエージェント、`@alice` はメンバー名に置き換えてください。ページを保存するとプログラムが開始されます。まずエージェントがリリースノートの下書きを作成し、次にメンバーへ公開可否の確認が届きます。1 日以内に返答がなければ、公開せずに終了します。

`norn` とだけタグ付けされたブロックや引用内のブロックは表示専用となり実行されません。プログラムの作成自体をエージェントに任せることもできます。ページへの追加を依頼すれば、保存時に返るチェッカーのエラーをエージェント自身が読んで修正してくれます。

## リクエストとリプライ

プログラムは「リクエスト」を発行することで処理を進めます。動詞ごとに求める回答の形式が異なります。

| 動詞 | 求める回答 |
| --- | --- |
| `run(who, task)` | 作業の実行と、プログラムが要求する形式での結果報告 |
| `confirm(who, question)` | Yes または No |
| `choose(who, question, [A, B])` | 提示した選択肢のいずれか 1 つ |
| `ask(who, question)` | 文章による自由回答 |

`~about=` で対象物、`~context=` で補足資料、`~by=` で期限（`4h`・`2d` などの期間または UTC 時刻）を指定します。`->wait` はリクエストの完了を待ちます。

すべてのリクエストは次の 6 通りのうち必ず 1 つのリプライで終了し、プログラムはそのすべてを処理する必要があります。分岐を 1 つでも漏らしたプログラムは起動されません。

| リプライ | 意味 |
| --- | --- |
| `Answered(x)` | 回答が得られた（`x` が回答内容） |
| `Refused(why)` | 依頼が辞退された |
| `NoReply` | 回答がないまま期限が過ぎた |
| `Broke(why)` | 試みたが実行できなかった、または到達できなかった |
| `Cancelled` | プログラム側がリクエストを取り消した |
| `Revoked` | リクエストの背後にある権限が失効した |

`->wait?` は「回答が得られたら続行し、それ以外のリプライならその時点でプログラムを終了する」短縮記法です。完全な構文は[言語仕様書](https://github.com/norn-lang/norn/blob/main/docs/spec.md)を参照してください。

## エージェントへのリクエストの動作

ハーネス名（`@claude`、`@codex`）や `@auto` へのリクエストは、メンションと同じ仕組みでエージェントを起動し、タスク内容と必須の回答形式を渡します。起動条件は丸括弧内に書きます。`@auto(~repo="acme/app", ~effort="high")` では `repo`、`pwd`、`machine`、`harness`、`model`、`effort` を指定できます。

エージェントは次のコマンドで回答し、その内容はエージェント名義で会話にも投稿されます。

```sh
xmatrix reply <request> 'Sound'
xmatrix refuse <request> '<why>'
xmatrix broke <request> '<why>'
xmatrix delegate <request> @Daniel '<why>'   # 別の参加者に回答を委任
xmatrix requests            # 自分が受けているリクエストと待機中の一覧
```

リクエストに回答できるのは、それを受け取った実行（Run）だけです。指定外の形式で回答すると拒否され、リクエストは未完了のまま残ります。リクエストが宙ぶらりんになることはありません。エージェントの起動失敗・停止・無回答終了が起きた場合、作業中断によるものであれば新しいエージェントへ 1 回だけ再割り当てされ、それ以外は `Broke` として終了し、プログラムで定義した分岐へ進みます。

## 人へのリクエストの動作

メンバー名やハンドル宛てのリクエストは、質問・選択肢・期限をまとめたカードとして会話に届き、**Needs you** にも表示されます。回答できるのはその本人だけで、**Decline** を選べば理由付きで辞退できます。沈黙が同意とみなされることはありません。`~by` の期限を過ぎると `NoReply` で終了し、`~by` がなければ回答があるまで待機します。

該当する名前のメンバーがいない、または複数一致した場合は、理由付きで `Broke` として終了します。

## リクエストを別の人に委任する

リクエストを保持している参加者は、他の 1 名に回答を委任（Delegate）できます。カード上の **Delegate…** から、会話内のメンバー、ハーネス名（`@claude`）、または会話内のインスタンス（`@claude:2`）と理由を指定します。プログラム側の進行は変わらず、期限も維持され、会話上には誰が誰に代わって回答したかが記録されます。委任先はそのまま回答するか、差し戻す（**Give back** または `xmatrix refuse`）ことができ、差し戻されると元の担当者に戻ります。未完了の間であれば、カード上の **Take back** で自分に取り戻すことも可能です。エージェントからの委任には `xmatrix delegate` を使います。

## プログラムの進行状況を見る

コードブロックの下には、プログラム全体がフローとして可視化されます。発行済みの各リクエストとその結果、現在誰の返答をいつまで待っているか、次に進み得るすべてのステップが一目でわかります。記述に不備があり実行できないブロックは、コード内の該当箇所と理由が表示されます。

各プログラムにはページとリンクされた専用会話（ページ名とブロック名から命名）が作られます。リクエスト・回答・最終結果がそこに投稿され、直近の作業を行ったエージェントもそのまま残るため、必要に応じて続けてフォローアップを書き込めます。

```sh
xmatrix page read <page-id>     # ページ内のプログラムと各実行状態を表示
```

## 変更と停止

プログラムはページ上の通常のテキストと同じように変更できます。

- **ブロックを編集して保存する。** 同じリクエスト記録に対してプログラムが再評価されます。同じ文言ですでに依頼済みのステップは再実行されず、新しく追加されたステップだけが実行されます。型・構文チェックに通らない変更は適用されません。
- **ブロック名を変更する**と、専用の会話を持つ別プログラムとして新しく開始されます。1 ページ内に同名のブロックが 2 つある場合、名前を変えるまでどちらも実行されません。
- **ブロック（またはページ自体）を削除する**と、プログラムは停止し、未完了のリクエストも取り消されます。プログラムの会話を停止した場合も同じです。
- **終了したプログラムのブロックを編集する**と、再実行されます。

プログラムは最後に保存したユーザーの権限で実行されます（エージェントが保存した場合は、そのエージェントの所有者の権限になります）。

## 繰り返し作業

`open Std` で Norn の標準ライブラリを読み込めます。定期ルーチンは 1 回の呼び出しで書けます。

````markdown
```norn run upkeep
open Std
routine(~every=7d, ~from=2026-11-16T09:00Z, ~who=@auto(~repo="acme/app"),
  ~otherwise=@claude(~repo="acme/app"), "Weekly upkeep: fix the riskiest open issue")
```
````

この例では指定時刻を起点に毎週 1 回実行されます。回答に至らなかった場合は `~otherwise` で指定したエージェントに一度だけ再依頼され、それでも失敗した回はプログラムの会話に報告されたうえでルーチン自体は継続します。タスク文言を書き換えると次回から反映され、過去の回が再実行されることはありません。

リマインダーは待機とメッセージ送信の組み合わせで書けます。

````markdown
```norn run renew-domain
after(2026-11-03T01:00Z)->wait
say(@alice, "The domain renews this week")
```
````

標準ライブラリには他にも `decide`（期限内に誰も答えなかった場合のみデフォルトを採用する選択）、`remind`、`followUp`、`schedule`、`all` が用意されています。

## 連携アプリからのイベント

プログラムは外部サービスのイベントを待機できます。

| ストリーム | 発火条件 |
| --- | --- |
| `ciFailed("owner/repo")` | リポジトリのデフォルトブランチでワークフローが失敗したとき |
| `prMerged("owner/repo")` | デフォルトブランチへプルリクエストがマージされたとき |
| `appEvent("sentry", ~feature="issue.created")` | [連携アプリ](connectors.md)からイベントが届いたとき（`~feature` 省略時はそのアプリのすべてのイベント） |

```norn
every(1d)->or(ciFailed("acme/app"))->forEach(_ =>
  run(@auto(~repo="acme/app"), "Check the build and fix what is broken")->wait)
```

このプログラムは毎日 1 回実行されるほか、CI が失敗した際にも即座に起動します。対象のリポジトリやアプリが Space に連携されている必要があります。

## 連携アプリでのアクション

プログラムは、[連携アプリ](connectors.md)に、指定した時刻にひとつの操作を実行させることができます。実行時にエージェントが動いている必要はありません。手順は 2 つです。**準備**は実行内容をそのまま固定して承認を得ます。この時点では何も送信されません。**公開**はそれを 1 回だけ実行します。

```norn
open Std
let post = (video, text, ~at) => spawn(~key=video, () => {
  let ready = X.prepareVideo("@acme", video, text)->wait?
  after(at)->wait
  X.publish(ready)->wait
})
ignore(all([
  post("<message id>/<attachment id>", "Stop pasting API keys.", ~at=2026-11-24T01:00Z),
  post("<message id>/<attachment id>", "One table for every agent.", ~at=2026-11-24T09:00Z),
]))
never()->wait
```

プログラムが始まるとすぐに、両方の投稿が承認を求めるので、まとめて一度に回答できます。その後、それぞれが自分の時刻に送信されます。リストに 1 行追加すると、新しい投稿についてだけ尋ねられます。最後の行はプログラムを動かし続けるので、リストに追加していけます。送信済みの投稿は、その行を残しても消しても、再び送信されることはありません。

承認の扱いは、そのアプリのただひとつの権限に従います。

| 権限 | プログラムがアクションを準備したとき |
| --- | --- |
| 読み書き（Read and write） | すぐに承認されます |
| 確認する（Ask first） | 会話の **Pending approvals** に表示され、Space 管理者が使用されるアカウント、本文、添付ファイルを見て回答します |
| 読み取り専用（Read only） | 拒否されます |

承認はその内容のそのアクション 1 件だけを対象とし、30 日間有効です。実行時に xMatrix は、接続とアカウントが承認時のものであること、承認した人がいまも承認できることを改めて確認します。どれかが成り立たなければ何も送信されず、プログラムは理由を受け取ります。結果が不明なアクションは失敗として報告され、再試行されません。動画の添付ファイルは、プログラム自身の会話にある必要があります。

`X.preparePost(account, text)` は動画なしの投稿を準備します。ほかのアプリのアクションは名前で指定し、入力はそのコマンドの 2 つの部分です。書き方は `xmatrix connector list` で確認できます。

```norn
type command = {target: string, text: string}
type done = {summary: string, url: option<string>}
let post: Actions.action<command, done> = Actions.action("slack", "post")

let ready = Actions.prepare(post, {target: "#releases", text: "4.2 is out."})->wait?
Actions.perform(ready)->wait
```

## エージェントからの単発の質問

回答を 1 つだけ得たいエージェントはプログラムを書く必要はありません。コマンドで直接質問し、回答を受け取れます。

```sh
xmatrix confirm @alice Ship 4.2 now? --by 1d --otherwise No
xmatrix choose @alice "Which plan?" Monthly Yearly
xmatrix ask @codex What does the migration change?
```

`--by` で期限、`--otherwise` で期限切れ時のデフォルト回答を指定します。質問は会話内に 1 回だけ表示されます。人宛ての場合は質問元エージェントと回答結果を示すカードになり、エージェント宛ての場合はリクエストになります。誤った内容や相手へ質問してしまった場合は `xmatrix cancel <request>` で取り消せ、カードにも取り消し済みと表示されます。

## メッセージ内のプログラム

1 つの `norn run` ブロックを含むメッセージを送信すると、その会話で単発のプログラムを開始できます。動作はページ上のプログラムと同じですが、送信後の編集はできず、各リクエストごとに新しいエージェントが起動します。

## 現在の制限

- `@claude:2` のような番号付きインスタンスをリクエスト先に指定することはできません。
- 「特定のプルリクエストがマージされる」「特定のリリースに含まれる」といった個別事実の待機にはまだ対応しておらず、待機できるのは上記のイベントストリームです。
- 保存前に編集による影響範囲をプレビューする機能はまだありません。
