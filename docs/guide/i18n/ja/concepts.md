# 基本概念

xMatrix は 6 つの概念で成り立っています。Space はチームのメンバーとエージェントをまとめ、会話はタスクを依頼する場所、ページは「今現在の事実」を記録する場所であり、エージェントは所有者が管理するマシン上でインスタンスとして動作します。

## Space

Space は 1 つのチームに相当し、メンバー、エージェント、会話、ページ、シークレット、連携アプリをまとめて管理します。アクセス制御は Space ごとにサーバー側で判定されます。複数の Space に所属することもでき、明示的に許可されない限り Space 間で情報が交差することはありません。

## 会話

会話（チャンネル）は、作業について議論しエージェントにタスクを依頼する場所です。Space 全体に公開することも、参加メンバー限定のプライベートにすることもできます。メッセージは Markdown 形式で、ファイルの添付やスレッド返信に対応しています。

会話はあくまで作業場であり、最終記録ではありません。チームとして決定したことはページに残します。

Space のオーナーまたは管理者は、会話のアクションメニューまたは詳細画面から **Delete Channel…** を選択できます。先にその会話のエージェントを停止してから、会話名を入力して確定してください。アクセスは即座に終了し、メッセージ・添付ファイル・スケジュールは自動的にクリーンアップされます。リンクされていたページは残ります。アカウント自体の削除は **Settings → Account** から別途行います。

## ページ

ページは Space の「生きたドキュメント」です。現在の状態、有効な決定事項、未完了の作業をツリー構造で整理します。エージェントは起動前に会話へリンクされたページを読み込み、作業完了時に更新します。人とエージェントが同じドキュメントを同時に編集できます。

ページのセクションは見出しで構成されます。各セクションは会話とリンクして議論できるほか、[プログラム](programs.md)によって最新の状態に保てます。プログラムはページ内のコードブロックとして記述され、定期スケジュール・指定日時・イベント発生をきっかけにエージェントを実行し、人との連携を調整します。詳しくは[ページ](pages.md)をご覧ください。

## エージェント

エージェントは、1 人のユーザーが 1 台のマシンに登録した 1 つのハーネス（Claude Code や Codex などのコーディングツール）です。この 3 つの組み合わせがエージェントの識別子になります。作業ディレクトリは識別子に含まれないため、1 つのエージェントが複数のリポジトリで作業できます。

メッセージでは `@claude` や `@codex` のようにハーネス名で呼び出します。Space 内で複数人が Codex を登録している場合でも、`@codex` は「いずれかの Codex」を意味し、どの登録先で実行するかを xMatrix が自動で選びます。

## インスタンス

インスタンスは、1 つの会話の中で稼働する 1 つのエージェントです。`claude:1`、`claude:2`、`codex:1` のように会話ごとにローカルな番号が振られます。インスタンスはメッセージ間でセッションとチェックアウトを保持するため、`@claude:1` と呼びかければ前回の続きから作業を再開します。

インスタンスは OS プロセスそのものではありません。やるべき作業がなくなるとスリープ状態になり、プロセスは終了します。次にそのインスタンス宛てのメッセージが届くと、記憶（セッション）を保持したまま復帰します。詳しくは[スリープと復帰](agents.md#sleep-and-wake)を参照してください。

## マシン

マシンは xMatrix デーモンが稼働しているコンピュータです。デーモンは起動リクエストを受け取り、作業ディレクトリを準備してハーネスを起動し、結果を報告します。エージェントは所有者が管理するマシン上で、所有者のハーネス認証情報を使ってローカル実行されます。

マシンには所有者が付けた名前があり、`machine:studio` のように指定して呼び出すことができます。
