# ページ

会話は流れが速く、後から振り返るのが大変です。ページ（Pages）は Space における「今現在の事実」— 現状、有効な決定事項、残タスク — をまとめておく場所です。人が会話で決め、エージェントがページを最新に保ちます。

## ページツリー

各 Space には 1 つのページツリーがあります。「誰が発言したか」ではなく「Space が何に取り組んでいるか」を軸に構成しましょう。ページは Markdown で書かれ、各見出しがセクションになります。先頭のトップレベル見出し（`# Name`）がページ名となり、ページ名を変更するとその見出しも書き換わります。

アプリで **Pages** を開くと、最近の更新に続いてツリー全体が表示されます。ターミナルからは次のコマンドで操作できます。

```sh
xmatrix page tree
xmatrix page tree --summaries
xmatrix page search <words>
xmatrix page read <page-id>
xmatrix page create "Billing" --under <parent-page-id>
xmatrix page rename <page-id> "Billing and invoices"
xmatrix page move <page-id> --under <other-page-id>
xmatrix page delete <page-id>
```

`page tree --summaries` を付けると、各ページの下に現在の状況を示す 1 行要約が表示されます。`page search` はクエリの全単語を含むページを検索し、該当セクションを `page:<id>#<section>` 形式で示して周辺テキストを表示します（入力した語順どおりに一致するページが優先されます）。規模の大きい Space では、ページを順番に読み漁るのではなくまず検索から始めましょう。

## 閲覧と編集

アプリ上では、複数のメンバーがライブカーソル付きでページを同時編集できます。エージェントは CLI 経由で編集し、その変更は開いているドキュメントへリアルタイムに反映されます。ロックは不要です。各セクションには現在開いている人や関連会話で作業中のエージェントが表示され、`xmatrix page read` でもエージェントに同じ情報が伝わります。

CLI からの編集は、読み込んだリビジョンの Markdown を新しい内容で置き換える形で行います。

```sh
xmatrix page read <page-id>                       # ページ本文とリビジョン番号を出力
xmatrix page edit <page-id> --base <revision> -f page.md
```

`--base` には最新リビジョンではなく、あなたが読み込んだときのリビジョンを指定します。その間に他の人やエージェントが行った変更は xMatrix が自動マージします。編集箇所が競合した場合のみ更新が拒否され、マージ先となる最新テキストが返されます。

長いページの一部だけを変更したい場合、全文を読み込む必要はありません。

```sh
xmatrix page read <page-id> --outline             # 見出し一覧とそれぞれのスラッグ・サイズを表示
xmatrix page read <page-id> --section <slug>      # 1 セクション（配下の見出しを含む）を読み込む
xmatrix page edit <page-id> --base <revision> --section <slug> -f section.md
```

セクション編集はそのセクションだけを書き換え、読み込み後に他セクションへ加えられた変更には一切影響しません。渡すテキストには見出し行を含めます。`page read --section` の出力には対象セクションを示すヘッダーが付くため、そのまま編集して `-f` で書き戻してもページ全体と誤認されることはありません。セクションの追加・削除・並べ替えを行う場合はページ全体を読み込んで編集します。

`xmatrix page read <page-id> --since <revision>` は指定リビジョン以降の差分だけを出力し、`xmatrix page history <page-id>` はリビジョン履歴を一覧表示します。

アプリ上で特定の箇所を誰が書いたか確認するには、段落にカーソルを合わせます。余白に執筆者と更新日時が表示されます。テキストを選択するとポップアップに同じ情報と執筆元の会話が表示され、クリックすればページ横に関連会話（その箇所が書かれた時点のメッセージ位置）が開きます。入力中でまだ保存されていない箇所には「being written」と表示されます。

### ページに書くべきこと

ページには「今現在正しいこと」だけを書きます。完了した項目や古くなった方針はログとして残さず、その場で書き換えるか削除してください。コミットハッシュ、Run ID、タイムスタンプなどの証跡はプルリクエストや会話に残し、ページからはそれらへリンクします。1 つの事実は 1 か所にだけ書き、他のページからはリンクで参照しましょう。

## ページと会話の連携

ページと会話は、どちらか一方がもう一方を参照するとリンクされます。リンクされたページは会話の上部にライブカードとして表示され、そこで起動したエージェントは作業前にそのページを読み込みます。

- メッセージ内で `[[` を押してページを、または `[[page#` を押してセクションを選択します。メッセージには `page:<page-id>` または `page:<page-id>#<heading-slug>` として保存されます。
- エージェントが実行中にページを読み込むと、その会話に自動リンクされます。
- 明示的にリンクするには `xmatrix page link <page-id> --block <heading-slug>` を使い、現在のリンク一覧は `xmatrix page linked` で確認できます。
- ページの更新通知が特定の会話へ届かないようにするには、会話上部のカードにカーソルを合わせて **Unlink from this conversation** を選ぶか、`xmatrix page unlink <page-id>` を実行します。一度リンク解除すると、エージェントがそのページを読み書きしても再度手動リンクされるまで解除状態が維持されます。

見出しスラッグは GitHub と同じ規則で、見出しを小文字化しスペースをハイフンに置換、記号を除いた文字列です（例：`## Open work` は `open-work`）。

### ディスカッション

ページ内のテキストを選択すると、その箇所に紐づいた会話（ディスカッション）を始められます。結論が出たら、結果をページ本文へ反映してディスカッションを解決（Resolve）します。

## プログラム

定期的な作業、指定日時の待機、イベント駆動の処理は、ページ上の「プログラム」として記述します。最新状態を保ちたいセクション内に `norn run` と名前を付けたコードブロックを書くだけです。プログラムは [Norn](https://norn-lang.org) 言語で記述し、ページを保存すると自動で動き始めます。ページの他の文章と同じように閲覧・編集できます。

12 時間ごとにエージェントへセクションを最新化させる例：

````markdown
## Open work

```norn run triage
open Std
routine(~every=12h, ~from=2026-11-16T09:00Z, ~who=@auto(~repo="acme/web"),
  ~otherwise=@claude(~repo="acme/web"),
  "Read the issues opened since the last run and update this section")
```
````

指定日時にリマインドを送る例：

````markdown
```norn run renew-domain
after(2026-11-03T01:00Z)->wait
say(@alice, "Renew the domain this week")
```
````

毎日 1 回実行しつつ、CI 失敗時にも即座に実行する例：

````markdown
```norn run build-watch
open Std
routine(~every=1d, ~from=2026-11-16T09:00Z, ~on=ciFailed("acme/web"),
  ~who=@auto(~repo="acme/web"), ~otherwise=@claude(~repo="acme/web"),
  "Check the build and fix what is broken")
```
````

時刻はすべて UTC です。`~from` は初回実行時刻と以降の周期の基準、`~who` は担当者、`~otherwise` はその回の実行が回答に至らなかったときに一度だけ追加依頼する相手を指定します。`~on` を使うと、`ciFailed("owner/repo")` や `prMerged("owner/repo")` などのイベント発生時にも実行を追加できます。プログラムは人への確認依頼、期限付きの待機、複数エージェント間の引き継ぎも行えます。言語仕様・リクエスト・イベント・制限の詳細は[プログラム](programs.md)をご覧ください。

### プログラムの動作の仕組み

- 各ブロックにはページとリンクされた専用の会話が用意され、リクエスト・回答・結果がそこに投稿されます。
- ブロックの下には、これまでに送ったリクエストと結果、現在誰の返答を待っているか、次に何をするかがリアルタイムに表示されます。記述どおりに実行できないブロックには理由が表示され、`xmatrix page edit` でもエラー内容が出力されます。
- プログラムは最後にページを保存したユーザーの権限で実行されます（エージェントが保存した場合はそのエージェント所有者の権限になります）。
- ブロックを編集するとプログラムが更新されます。すでに完了したリクエストが再度送られることはありません。ブロックを削除するとプログラムが停止します。

```sh
xmatrix page read <page-id>     # ページ内のプログラム一覧と各実行状態を表示
```

## 公開ページ

Space のオーナーまたは管理者はページを外部公開できます。公開すると、サインイン不要で誰でも公開 URL から閲覧でき、エージェントがページを更新すると閲覧中の画面もリアルタイムに更新されます。

公開できるのは、Space の全メンバーが閲覧可能なページに限られます。あるページを公開しても、その配下の子ページは自動的には公開されません。公開ページの最新化はエージェントが行えますが、公開・非公開の切り替えは人だけが行えます。
