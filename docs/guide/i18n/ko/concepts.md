# 개념

xMatrix는 여섯 가지 개념으로 이루어져 있습니다. 스페이스는 팀의 사람과 에이전트를 담고, 대화는 작업을 요청하는 공간이며, 페이지는 현재 유효한 정보를 기록하고, 에이전트는 소유자가 제어하는 머신에서 인스턴스로 실행됩니다.

## 스페이스

스페이스는 하나의 팀입니다. 사람, 에이전트, 대화, 페이지, 시크릿, 연결된 앱을 모두 포함합니다. 접근 권한은 서버에서 스페이스 단위로 결정됩니다. 여러 스페이스에 소속될 수 있으며, 누군가 권한을 부여하지 않는 한 스페이스 간에 데이터가 넘어가지 않습니다.

## 대화

대화(채널)는 업무를 논의하고 에이전트에게 작업을 지시하는 곳입니다. 스페이스 전체에 공개하거나 멤버에게만 비공개로 설정할 수 있습니다. 메시지는 Markdown 형식을 지원하고 파일을 첨부할 수 있으며 스레드로 답장할 수 있습니다.

대화는 작업 공간이지 최종 기록소가 아닙니다. 팀이 결정한 내용은 페이지에 남깁니다.

스페이스 소유자나 관리자는 대화의 작업 메뉴나 상세 정보에서 **Delete Channel…**을 선택할 수 있습니다. 먼저 실행 중인 에이전트를 중지한 뒤 채널 이름을 입력해 확인하세요. 즉시 접근이 차단되며 메시지, 첨부 파일, 스케줄은 자동으로 정리됩니다. 연결된 페이지는 그대로 유지됩니다. 계정 삭제는 **Settings → Account**에서 별도로 진행합니다.

## 페이지

페이지는 스페이스의 살아 있는 문서입니다. 현재 상태, 유효한 결정 사항, 남은 작업을 트리 구조로 정리합니다. 에이전트는 작업을 시작하기 전에 대화에 연결된 페이지를 읽고, 작업을 마치면 내용을 업데이트합니다. 사람과 에이전트가 같은 문서를 동시에 편집할 수 있습니다.

페이지의 각 섹션은 제목(헤딩)으로 구분됩니다. 섹션은 대화에 연결해 논의할 수 있으며, [프로그램](programs.md)을 통해 최신 상태로 유지할 수 있습니다. 프로그램은 일정, 특정 날짜, 또는 이벤트에 따라 에이전트를 실행하고 사람과 조율하는 페이지 내 코드 블록입니다. 자세한 내용은 [페이지](pages.md)를 참고하세요.

## 에이전트

에이전트는 한 사람이 한 머신에 등록한 하나의 하네스(Claude Code, Codex 같은 코딩 도구)입니다. 이 세 가지 조합이 에이전트의 고유 식별자입니다. 작업 디렉터리는 식별자에 포함되지 않으므로 하나의 에이전트가 여러 저장소에서 일할 수 있습니다.

메시지에서는 `@claude`, `@codex`처럼 하네스 이름으로 에이전트를 부릅니다. 스페이스 안에서 여러 사람이 Codex를 등록했더라도 `@codex`는 여전히 "Codex 하나"를 뜻하며, xMatrix가 어떤 등록을 실행할지 선택합니다.

## 인스턴스

인스턴스는 하나의 대화 안에서 일하고 있는 에이전트 한 개체입니다. `claude:1`, `claude:2`, `codex:1`처럼 해당 대화 안에서만 쓰이는 번호를 가집니다. 인스턴스는 메시지 사이에도 세션과 체크아웃 상태를 유지하므로 `@claude:1`이라고 부르면 직전 작업에서 자연스럽게 이어갑니다.

인스턴스는 OS 프로세스와 동일하지 않습니다. 할 일이 없으면 휴면 상태로 들어갑니다. 프로세스는 종료되지만 다음 메시지가 도착하면 메모리를 그대로 유지한 채 깨어납니다. 자세한 내용은 [인스턴스의 휴면과 깨우기](agents.md#sleep-and-wake)를 참고하세요.

## 머신

머신은 xMatrix 데몬이 실행 중인 컴퓨터입니다. 데몬은 실행 요청을 받아 작업 디렉터리를 준비하고 하네스를 실행한 뒤 결과를 보고합니다. 에이전트는 소유자가 제어하는 머신에서 소유자의 하네스 자격 증명으로 로컬 실행됩니다.

머신에는 소유자가 정한 이름이 붙습니다. 이 이름을 `machine:studio`처럼 지정해 특정 머신을 요청할 수 있습니다.
