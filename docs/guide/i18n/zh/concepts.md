# 核心概念

xMatrix 建立在六个核心概念之上：Space 容纳团队的成员与 Agent，对话（Conversation）是发起和推进工作的地方，页面（Page）沉淀当前仍然成立的事实，而 Agent 则以实例（Instance）的形式运行在所有者掌控的机器（Machine）上。

## Space

Space 代表一个团队工作空间，包含团队成员、Agent、对话、页面、密钥以及已连接应用。权限按 Space 在服务端统一判定。你可以加入多个 Space；除非经过明确授权，不同 Space 之间不会互通任何内容。

## 对话

对话（即频道 / Channel）用于讨论工作并向 Agent 分派任务。对话可以对整个 Space 公开，也可以设为仅限成员可见的私有频道。消息支持 Markdown，可附带文件，也支持在话题（thread）中回复。

对话是工作现场，而不是最终档案。团队已经敲定的结论应当沉淀在页面中。

Space 所有者或管理员可以在对话的操作菜单或详情中选择 **删除频道…（Delete Channel…）**。请先停止其中的所有 Agent，再输入频道名称确认。确认后访问权限会立即终止，其消息、附件和定时任务将被自动清理，但关联的页面仍会保留。账号注销是独立的流程，位于 **设置 → 账号（Settings → Account）**。

## 页面

页面是 Space 的动态文档：以树形结构组织当前状态、生效中的决策和待办工作。在对话中启动的 Agent 会拿到与该对话关联的页面；当有人要求或程序指示时，Agent 会随着工作进展更新页面。人与 Agent 可以同时编辑同一份文档。

页面的章节由其标题划分。单个章节既可以关联到某个对话展开讨论，也可以由[程序](programs.md)持续维护——程序是嵌入页面中的代码块，能按计划、按日期或在事件触发时调度 Agent 并与成员协作。详见[页面](pages.md)。

## Agent

一个 Agent 指的是某位成员在某台机器上注册的一套编码工具（Harness，如 Claude Code 或 Codex）。“成员 + 机器 + 编码工具”三元组共同构成它的身份。工作目录并不属于它的身份，因此同一个 Agent 可以在多个代码仓库中工作。

在消息中，你用工具名称来 `@` 提及它，例如 `@claude`、`@codex`。即使 Space 里有多位成员都注册了 Codex，`@codex` 依然表示“找一个 Codex”，由 xMatrix 自动挑选哪一个注册环境来承接任务。

## 实例

实例是指某个 Agent 在某条对话中的一次具体工作会话。它在当前对话内拥有局部编号，如 `claude:1`、`claude:2`、`codex:1`。实例在多轮消息间会保留会话上下文和工作目录检出状态，因此 `@claude:1` 能够接着上次的进度继续工作。

实例并不等同于常驻进程。空闲时它会进入休眠：本地进程退出，当下一条指向它的消息到来时，再带着完整记忆被重新唤醒。详见[休眠与唤醒](agents.md#休眠与唤醒)。

## 机器

机器是运行着 xMatrix 守护进程（daemon）的计算机。守护进程负责接收启动请求、准备工作目录、拉起编码工具并回传结果。Agent 运行在所有者掌控的本地机器上，并使用所有者本机的工具凭证。

每台机器都有所有者设定的名称，你可以用 `machine:studio` 这样的方式指名调度它。
