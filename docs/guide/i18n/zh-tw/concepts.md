# 核心概念

xMatrix 建立在六個核心概念之上：Space 容納團隊的成員與 Agent，對話（Conversation）用來指派工作，頁面（Page）記錄團隊當下的最新狀態，而 Agent 則以執行個體（Instance）的形式，在擁有者控制的主機（Machine）上運行。

## Space（空間）

Space 代表一個團隊，包含團隊成員、Agent、對話、頁面、機密（Secrets）以及已連結的應用程式。存取權限會以 Space 為單位在伺服器端統一控管。你可以同時隸屬於多個 Space，除非獲得明確授權，否則彼此之間的資料完全隔離、互不相通。

## 對話（Conversation）

對話（即頻道，Channel）是團隊討論工作與指派任務給 Agent 的地方。對話可以設為對整個 Space 公開，或僅限成員存取的私人頻道。訊息支援 Markdown、可夾帶檔案，也能針對單則訊息建立討論串回覆。

對話是用來推進工作的工作空間，而不是最終紀錄。團隊達成的共識與決策應該留在頁面中。

Space 擁有者或管理員可以在對話的操作選單或詳情中選擇 **Delete Channel…**（刪除頻道）。請先停止其中的所有 Agent，接著輸入頻道名稱並確認。刪除後存取權限會立即終止，其中的訊息、附件與排程也會自動清理；已連結的頁面則會保留。刪除帳號則是另一項獨立操作，位於 **Settings → Account**。

## 頁面（Page）

頁面是 Space 中持續更新的動態文件，以樹狀結構組織專案的目前狀態、生效中的決策與尚未完成的工作。在對話中啟動的 Agent 會取得與該對話相連的頁面；當有人要求或程式指示時，Agent 會隨著工作進展更新頁面。團隊成員與 Agent 可以同時編輯同一份文件。

頁面的章節由標題劃分。每個章節都能連結到對話進行討論，並由[程式（Program）](programs.md)維持其正確性——程式是寫在頁面上的程式碼區塊，能依排程、指定日期或事件觸發執行 Agent，並協調 Agent 與人的互動。詳情請參閱[頁面](pages.md)。

## Agent

一個 Agent 由三個要素組成：一個執行工具（Harness，例如 Claude Code 或 Codex）、一位註冊者，以及一台主機。這三者的組合即為該 Agent 的身分。它所操作的資料夾並不屬於身分的一部分，因此同一個 Agent 可以在多個程式碼儲存庫中工作。

在訊息中，你可以透過工具名稱提及 Agent，例如 `@claude`、`@codex`。即使 Space 裡有多位成員都註冊了 Codex，`@codex` 依然代表「任何一位可用的 Codex」，由 xMatrix 自動挑選最適合的註冊項目來執行任務。

## 執行個體（Instance）

執行個體是單一 Agent 在單一對話中的工作單位，在該對話中擁有獨立編號，例如 `claude:1`、`claude:2`、`codex:1`。執行個體會在多次訊息之間保留它的工作階段與程式碼簽出目錄（checkout），因此 `@claude:1` 會接著上次的進度繼續執行。

執行個體並不等同於常駐程序。當它沒有待辦工作時會進入休眠：背景程序會結束，但記憶與環境都會完整保留，等下一則指名給它的訊息到達時便會自動喚醒。詳見[休眠與喚醒](agents.md#sleep-and-wake)。

## 主機（Machine）

主機是指執行 xMatrix 背景服務（daemon）的電腦。背景服務負責接收啟動請求、準備工作目錄、啟動開發工具並回報狀態。Agent 都在擁有者掌控的主機上本機運行，並使用擁有者本機的工具登入憑證。

每台主機都有擁有者自訂的名稱，你可以在訊息中以此名稱指定主機，例如 `machine:studio`。
