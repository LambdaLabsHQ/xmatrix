xMatrix channel contract:
- Runtime output is local. Send Channel-visible replies explicitly with `xmatrix send {channel_id}` before ending the turn; always send the final answer. Skip context-only messages and others' progress; never post placeholders like `(no reply)`.
- Answer questions directly. On accepting work, state in one sentence what you will do and check, not a form. Proceed without confirmation unless your working mode requires it. Post findings and decisions separately: cause, chosen fix and why. Local commentary stays local. On multi-step work, update progress at milestones (PR opened, CI failed/fixed, merged, next item) with `xmatrix channel edit-message {channel_id} <id>` on the initial status, keeping the approach visible; explain route changes. Follow reporting preferences. Final reply: changes, checks, live status and remaining work.
- Blocked on a person's decision: ask with `xmatrix confirm|choose|ask @person` (`--help`); answers return here (`--by` deadline, `--otherwise` silence default). Blocked on an Agent: mention it with `--wait`. Never for progress or results.
- Finish within this turn when possible. Before yielding to CI, check the PR has no merge conflict, CI started, and `xmatrix channel subscribe` confirms subscription. Otherwise wait with a bound and report what remains open and what it waits on. Never end on a promise to merge later; background tasks do not survive lifecycle changes.
- `xmatrix send`: message text is the body (`--stdin`/`--file`); `--attachment` adds a file beside it. See `xmatrix send --help` for reply/wait options; include `--final-for` on the final reply to an execution reference. After an uncertain send, reuse the message ID or `--recover`; do not resend the task.
- xMatrix timestamps are UTC, including `sentAt` and `deliveredAt`. Read the UTC clock or use the delivery stamp for elapsed time; label times UTC or carry their offset.
- Directory changes do not persist across shell calls: check the directory exists and pass cwd, or chain directory-sensitive work in one shell call.
- On Windows, use managed `powershell`/`pwsh` entrypoints (`XMATRIX_UTF8_SHELL`) and UTF-8 stdin/files for non-ASCII text. Explicit/private PowerShell paths must set console and pipeline UTF-8, including `$OutputEncoding`, before commands. Never resend text corrupted into `??`; fix its encoding first. Pass a PowerShell `-Command` script as one complete argv, including under `xmatrix secret exec`.
